# External reader oracle facts (`C0`)

This folder holds independent ground-truth facts extracted directly from the raw XML, ZIP, and YAML solution files tracked in `tests/fixtures/` and `tests/eval/roles/cases/` at base commit `b75744acd5e9bbc27387ec2acda2bf65bd675fd2`, authored blind to all Phase C production reader branches (`C1`–`C5`).

## Contract

1. **Independence**: None of the facts in `facts/*.json` were generated by `PowerOps.Core`. Each file records structural facts read directly from the raw solution files so `C1` (unified XML/ZIP/YAML readers) and `C2` (two-sided diff) can be graded against an external source of truth.
2. **Absent vs explicit false**: Any XML element, XML attribute, YAML key, or JSON property that is absent in the raw file is recorded as `null`. `false` and `0` appear only when the raw source explicitly wrote `0`/`false`.
3. **Cross-layout parity**: `powerops-seed-v1-xml.json` and `powerops-seed-v1-yaml.json` describe the same `PowerOpsSeed` v1 solution across XML unpack and Dataverse Git YAML layouts (`entities/pops_workitem/attributes/*.yml` + `modernflows/`), and `column-level-security-unmanaged.json` + `column-level-security-managed.json` cover unmanaged and managed ZIP exports.
4. **Both Field Security Profile XML layouts**: `column-level-security-*.json` covers Microsoft's `customizations.xml` `<FieldPermissions><FieldPermission><EntityName>...</FieldPermission></FieldPermissions>` layout, while `eval-solution-05.json` covers unpacked `FieldSecurityProfiles/*.xml` `<Permissions><Permission entityname="..." attributelogicalname="..." ... /></Permissions>` layout.
5. **Freeze & integrity**: `manifest.sha256` freezes the LF-normalized SHA-256 of `schema.json`, every `facts/*.json` file, and `bench/canaries/readers/commitments.json`. Run `python3 bench/canaries/readers/verify_commitments.py --check` to verify every `source_sha256`, canary `input_sha256`, and `manifest.sha256` entry.
