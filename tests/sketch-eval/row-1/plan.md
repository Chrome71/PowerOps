# Supplier onboarding

## Goal

1. An employee asks for a new supplier and sees where the request stands.
2. Procurement works the open requests, and the procurement lead decides the escalated ones.
3. The lead sees how many requests come in and how long a decision takes.

## Screens

A canvas app for requesters, a model-driven app for procurement and a Power BI report for the lead.

- My requests (canvas, browser): who: any employee, a few times a month. Job: see each of my requests and its status, and start a new one. First look: the selected request's status and the sentence that says what happens next.
- New request (canvas, browser): who: the requester. Job: enter the supplier and the reason, and submit. First look: the first empty field, then the submit button.
- Request detail (canvas, browser): who: the requester. Job: read one request and its decision. First look: the status and the decision sentence.
- Supplier requests (model-driven view): who: procurement officers and the lead, daily. Job: find the requests to work. First look: the oldest open request.
- Supplier request (model-driven form): who: the procurement lead. Job: read a request and decide an escalated one. First look: the decision comment field.
- Supplier (model-driven form): who: procurement and finance. Job: keep a supplier's details. First look: the supplier's name and general fields.
- Supplier documents (model-driven view): who: procurement, weekly. Job: find the documents to renew. First look: the earliest expiry date.
- Supplier onboarding overview (Power BI page): who: the procurement lead, weekly. Job: see how many requests come in and how long a decision takes. First look: the summary cards, then the 12-month trend.

## Assumptions

None.
