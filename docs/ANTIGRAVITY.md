# PowerOps with Antigravity (Gemini)

PowerOps supplies the same seven core skills, the portable `powerops-specialists` skill (six domain procedures) and the CLI-backed `powerops mcp` server to Gemini models in Google Antigravity (`agy` CLI, Antigravity IDE and Antigravity 2.0). Equivalent procedures do not establish equal model performance, installed Microsoft connectors or live harness enforcement.

## Use the skills and plugin

Install the CLI first ([Install](../README.md#install)): the skills and MCP server call `powerops` from `PATH`. Then choose repository copies or the Antigravity plugin:

- **Repository copies (recommended for teams):** run `powerops skills install --agent antigravity` (or add `--force` when deliberately replacing older copies). This writes the skills to `.agents/skills/`, which Antigravity discovers automatically across workspace subdirectories. Teams storing skills at another path inside a repository can point `.agents/skills.json` at that folder (for example, `{"entries": [{"path": "skills"}]}`).
- **Antigravity plugin (personal setup):** from a clone, run `agy plugin install <clone>/plugins/antigravity` to install the eight skills and `mcp_config.json` into `~/.gemini/config/plugins/powerops`. To update the plugin after pulling new commits, run `agy plugin uninstall powerops` and then `agy plugin install <clone>/plugins/antigravity`. Do not install both the plugin and repository copies in the same project unless you want duplicate skill entries.
- **Standalone MCP server (without the plugin):** run `agy mcp add powerops powerops mcp`.

In a source checkout of PowerOps itself, Antigravity can read `skills/<name>/SKILL.md` directly even before skills are installed. From a built checkout, the local CLI is `dotnet src/PowerOps.Cli/bin/Debug/net10.0/powerops.dll`; an older globally installed CLI will not include unbuilt changes.

Example: "Use powerops-specialists for workflow-logic plan-advice on docs/plans/orders, tenant: offline. Review the approval state model and return proposed plan lines." Read [the specialist skill](../skills/powerops-specialists/SKILL.md), then only the reference it selects. It works in one session unless delegation was requested.

## Antigravity and Gemini specifics

- **Questions (`ask_question` vs print mode):** Interactive Antigravity exposes `ask_question`, whose UI adds option numbers and an "Other" free-text choice automatically. Pass unnumbered options without an "In your own words" entry, with `(Recommended)` on the first option, then still write numbered options ending with `In your own words` into `decisions.md`. In `agy -p` print mode `ask_question` is unavailable: print numbered options in plain text and tell the user how to reply (`1 2 1`, or in their own words) rather than asking with a single plain sentence (M39 observed a plain-sentence failure when interactive choices were unavailable).
- **Plan/Execute mode (`exit_plan_mode`) vs `powerops-plan`:** In Antigravity's two-phase Plan mode, file-writing tools (`write_file`, `edit_file`) are refused during a planning turn until `exit_plan_mode` hands control to the execution turn, while `ask_question` works in both phases. Run `powerops-plan` question rounds in normal interactive mode so each round writes `plan.md` and `decisions.md` before ending the turn, or hand off file writes through `exit_plan_mode`. Always run `powerops-implement` in execution mode.
- **Fresh-context roles:** Start `powerops-prototype`, `powerops-review-sketch`, `powerops-review-plan`, `powerops-verify` and `powerops-review-security` with `invoke_subagent` (`TypeName: "self"`, `Model: "inherit"`), passing only the role skill path, the plan folder, required inputs and objective. `invoke_subagent` starts a fresh conversation with no inherited chat history, so a role that ran that way records `fresh-context: yes` (or `judge: fresh context` for the sketch judge) on the session's Gemini model. Do not use `swarm` with `fork` for fresh-context reviews, because `fork` copies conversation history. Otherwise give the person the request for a new session and wait, and never report `fresh-context: yes` from a planning chat. Keep `skills/powerops-review-sketch/SKILL.md`, `skills/powerops-verify/SKILL.md` and `skills/powerops-review-security/SKILL.md` unchanged.
- **Model selection and lazy MCP tools:** Keep `Model: "inherit"` so roles and specialists use the Gemini model and thinking tier configured in the session; never translate Claude aliases (`opus`, `sonnet`, `haiku`) into guessed model names. Antigravity exposes MCP tools either eagerly (`mcp_<server>_<tool>`) or lazily through schemas under `<appDataDir>/mcp/<server>/<tool>.json` invoked via `call_mcp_tool`. Inspect the connected MCP servers and available tool schemas before claiming a Microsoft connector is available or absent.
- **Sandbox, browser subagent and hooks:**
  - Antigravity's standard command sandbox (`BypassSandbox: false`) blocks network access and writes outside the workspace and `/tmp`. Offline PowerOps commands (`analyze`, `diff`, `inventory`, `manifest`, `test`, `rules`, `settings validate`, `plan status`, `plan sign-off`, `skills install`) run inside the sandbox. Live `pac`/`az` reads or imports go through `powerops mcp` or user-approved unsandboxed commands after the user names the environment. When building or testing PowerOps itself from source inside a Linux sandbox where `~/.local` or `/run/user/1000` is unavailable, run `dotnet build --no-restore`, `dotnet test --no-restore` and `dotnet format --verify-no-changes --no-restore` with `XDG_RUNTIME_DIR=/tmp XDG_DATA_HOME=/tmp NUGET_PACKAGES=~/.nuget/packages DOTNET_CLI_TELEMETRY_OPTOUT=1 TESTINGPLATFORM_TELEMETRY_OPTOUT=1`.
  - Antigravity's built-in `browser` subagent is sandboxed from arbitrary workspace paths, and `powerops-prototype` writes only under `docs/plans/<name>/mockups/`. Unless a local workspace renderer is available, `powerops-prototype` records `"not rendered"` in its report rather than staging sketches outside `mockups/`.
  - Antigravity's `.agents/hooks.json` `PreToolUse` contract sends camelCase `toolCall` payloads (`name: "run_command"`, `args.CommandLine`) and reads JSON `{ "decision": "allow" | "deny" }` from stdout (default 30 s timeout), whereas `powerops deploy gate` reads `tool_name` / `tool_input` and blocks on exit code `2` with empty stdout. Do not wire `powerops deploy gate` directly into `.agents/hooks.json` without an adapter, and treat MCP elicitation forms and long-call timeouts in Antigravity as not checked ([HARNESS.md](HARNESS.md)).

## Capability comparison

| Capability | Claude Code | Codex | Antigravity (Gemini) | Evidence or limit |
|---|---|---|---|---|
| Plan, prototype, sketch judge, plan review, implement, verify, security review | Seven core skills | The same seven skill bodies | The same seven skill bodies | Generated-copy tests; only Claude's fork/model frontmatter differs |
| Apps, Automate, BI, design, workflow logic, Copilot Studio advice | Six native agents or portable specialist skill | Portable specialist skill | Portable specialist skill | Generated from the Claude sources, with relative reference checks; advisory, not evaluated |
| CLI and MCP checks, dry runs and deploy gate | `powerops` / `powerops mcp` | Same executable and server | Same executable and server | Shared command and MCP tests; stdio inherits env in Antigravity docs |
| Fresh-context review | Installed review skills fork | Worker with no inherited history, or a new session | `invoke_subagent` (`self`) with no inherited history, or a new session | Never report fresh context from a planning chat or a `swarm` `fork` |
| Model choice | Native specialists pin Opus; maintenance agents use Sonnet/Haiku | Portable skill keeps the selected session/parent model | Portable skill keeps the selected session/parent Gemini model | No fixed model alias or account tier required; no claim of equal accuracy |
| Questions | `AskUserQuestion` | `request_user_input` in Plan mode, else plain text | `ask_question` in interactive sessions, numbered plain text in print mode | The person still answers approvals and sign-off; do not auto-answer |
| Tenant confirmation and blocking hooks | Client-specific | Client-specific | Hooks use JSON stdout (`toolCall`), not exit-2; forms not checked | [HARNESS.md](HARNESS.md) records differences; skill instructions do not install hooks |
| Microsoft product tools | Separately installed servers/skills | Separately installed servers/skills | Eager or lazy (`call_mcp_tool`) MCP servers and skills | Discover actual tools; absent means unavailable, not an invented fallback |
| PowerOps repository maintenance | Five repo agents and four JavaScript workflows | Adapted procedures using Codex tools | Adapted procedures using Antigravity tools | No Claude workflow runtime or native agent registration is implied |

Discover tools before live work. A tool named in a Claude `tools:` list does not mean it is connected in Antigravity, and that list is not an Antigravity permission control. Never copy `.claude/settings.local.json`, sign-ins or tenant-specific configuration into `.agents/` or plugin folders. Use [the hand-off guide](HANDOFF.md) for a user's own connections.

## Repository maintenance procedures

These apply to contributing to PowerOps itself, not to building a customer's Power Platform solution. Read the matching file below for its task procedure; ignore its Claude YAML model/tool configuration. Use Antigravity's tools under the current sandbox and approval rules, and note that `.agents` read-only instructions are not a separate sandbox. The user's request and `AGENTS.md` take precedence, including authorization to commit.

| Work | Procedure source | Antigravity adaptation |
|---|---|---|
| Check Microsoft claims | [.claude/agents/powerops-researcher.md](../.claude/agents/powerops-researcher.md) | Use `search_web` or official documentation tools; answer, release status/date, sources, confidence and unverified items; no edits |
| Design a PowerOps change | [.claude/agents/powerops-designer.md](../.claude/agents/powerops-designer.md) | Read-only inspection (`read_file`, `run_command` search), smallest complete approach, affected files, tests, risks and deferrals |
| Implement a bounded change | [.claude/agents/powerops-implementer.md](../.claude/agents/powerops-implementer.md) | Tests first for logic; build/test/format; commit only when requested; new branches use `antigravity/` or Conventional prefixes |
| Review a diff | [.claude/agents/powerops-reviewer.md](../.claude/agents/powerops-reviewer.md) | Inspect connected code, return substantiated file/line findings; no edits or git mutations |
| Mechanical chores | [.claude/agents/powerops-chores.md](../.claude/agents/powerops-chores.md) | Touch only named files; stop on ambiguous steps; no implicit commit |

Use one agent by default (`AGENTS.md`). If the user explicitly asks for one of these multi-agent workflows, carry out the equivalent with `invoke_subagent` (`TypeName: "self"`, `Model: "inherit"`) or `swarm` as appropriate; do not execute `.claude/workflows/*.js` with Node. Inherit the model unless the user requests otherwise, respect available concurrency, and wait for all required results. A missing worker result is a failed or incomplete check, never approval.

- **Design panel:** three independent read-only proposals (smallest solution, risk, contributor/user experience), then two independent reviewers score each proposal 1-10. Return proposals, scores, reasons and missing responses. Source: [.claude/workflows/design-panel.js](../.claude/workflows/design-panel.js).
- **Review PR:** review the named base (default `origin/main`, fallback `main` with disclosure), committed and uncommitted changes, through correctness, security and simplicity; at most five findings per lens. Independently try to refute each finding, deduplicate and report survivors, failed checks and empty diffs. Source: [.claude/workflows/review-pr.js](../.claude/workflows/review-pr.js).
- **Implement feature:** at most five supplied tasks in order, one implementer and one independent reviewer per task. The commit-per-task form requires a clean working tree and an explicit request to commit; otherwise implement the requested bounded change without commits. Build, test and format must pass. Review the actual diff or commit, stop on High/Medium findings or missing review, and mark remaining tasks skipped. Never push. Source: [.claude/workflows/implement-feature.js](../.claude/workflows/implement-feature.js).
- **Verify research:** answer each supplied question from sources, then use two independent attempts to refute it from current sources. Mark confirmed only when both ran and neither refuted, and explain that agreement is not proof. Report missing checks and unresolved contradictions. Source: [.claude/workflows/verify-research.js](../.claude/workflows/verify-research.js).

If independent subagents are unavailable, offer a sequential pass and label it as such; do not claim it reproduced an independent panel.
