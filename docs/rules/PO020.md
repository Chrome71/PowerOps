# PO020: Power Pages Web API is enabled for a table with no fields setting

Severity: warning

## What it finds

A site setting `Webapi/<table>/enabled` that is `true` (trimmed, ignoring case), in a site that has no `Webapi/<table>/fields` setting with a value and no `Webapi/<table>/UseFieldsFromView` setting that is `true`. There is one finding per `enabled` setting, named by the setting's name.

Only active site settings (component type 9) count. Setting names are compared ignoring case, and the settings must belong to the same site. A fields setting with an empty value counts as none. A fields setting of `*` counts as a fields setting here; PO019 reports that.

When `UseFieldsFromView` is `true` and the table has no fields setting, the rule gives no finding. It can't tell whether the view holds a column, because it doesn't read the view. Instead `analyze` prints one `note:` line on stderr and the exit code doesn't change: `PO020 not checked for table '<table>': UseFieldsFromView is True, and the view that holds the columns is not read.` The input it needs is the table's Power Pages Web API Columns system view.

The rule reads the `powerpagecomponents/` folder of the enhanced data model in a solution, unpacked or in a zip. It does not read the `.powerpages-site/` layout. Learn doesn't document the export layout; the `value` key in a site setting's `content` was observed in the core-portal solution of microsoft/gov-apptemplates and in the Contoso Real Estate sample.

## Why it matters

Learn says the fields setting is required unless `UseFieldsFromView` is `True` and the table's Power Pages Web API Columns system view has at least one eligible column. A table that is enabled with neither is not set up the way Learn describes. Learn's security advice is to enable the Web API only for required tables, with an explicit list of columns.

## How to fix

Add a `Webapi/<table>/fields` setting with the logical names of the columns the site needs. Or set `Webapi/<table>/UseFieldsFromView` to `True` and add the columns to a public system view of the table named Power Pages Web API Columns. Learn says `UseFieldsFromView` is available in site version 9.8.8.x and later. An export doesn't show the site's version (the site record in the core-portal solution holds none), so the rule can't check it. If the site doesn't need the Web API for the table, set `enabled` to `false`.

Microsoft's own sample sites trip some of the Power Pages rules, so the message says "before Production", not "now".

## Suppress

To accept the finding for now, run `powerops baseline` and use `powerops analyze --baseline powerops-baseline.json`. A baselined finding is matched on solution, rule, component and message.
