# PO033: Custom security role has no privilege to open a model-driven app

Severity: warning

## What it finds

A security role in the solution that has privileges on tables but none of `prvReadAppModule`, `prvReadUser` and `prvReadUserQuery`. There is one finding per role, named by the role's name:

- `Role '<role>' has table privileges but none of prvReadAppModule, prvReadUser and prvReadUserQuery, so a user who holds only this role may not be able to open a model-driven app.`

The three are the privileges Read on Model-driven App, Read on User and Read on Saved View. A role that holds any one of them is quiet, and so is a role with no table privilege (a table privilege is `prv` plus Create, Read, Write, Delete, Append, AppendTo, Assign or Share plus a table's schema name; names are compared ignoring case). A role whose id is one of Learn's documented role templates is skipped: a system role carried in a solution is not custom. The message says "may" because a user can hold Basic User or App Opener beside the role.

A role file with no `RolePrivileges` element gives one `note:` line on stderr, shared with [PO034](PO034.md), and the exit code doesn't change: `PO033 and PO034 not checked for role '<role>': its file has no RolePrivileges element, so its privileges are not known.`

The rule reads `Roles/<name>.xml` in an unpacked folder (one level, as `pac solution unpack` writes it), and the `Role` elements of a zip's `customizations.xml`. It does not read the YAML layout. A role's privilege depth (`level`) is not read.

Learn's part: "Privileges required to view and access apps" names the Read privilege on the Model-driven App table, and "Create or edit a security role to manage access" names Read User and Read Saved View, in words, among the minimum privileges (with App Opener to open a model-driven app). The `prv` names of the three come from the troubleshooting page for Dynamics 365 App for Outlook. Learn doesn't list the privileges of App Opener by name, so the rule checks only these three. Observed in exports: privilege names are `prv` plus verb plus the table's schema name in every role file read.

Limits: holding any one of the three silences the rule, which is far weaker than Learn's minimum. A role with Create and Write on the Model-driven App table but no `prvReadAppModule` still gets the finding, although Learn says a user with both is a maker who can open every app; no export read so far has a role of that shape.

## Why it matters

Learn says users need a security role with the minimum privileges for common tasks such as opening model-driven apps, and names App Opener as the role to assign or copy. A custom role that holds table privileges and none of the three may leave its users unable to open the app.

## How to fix

Copy the role from App Opener, or give its users App Opener as well, and test the app as a user who holds only those roles.
