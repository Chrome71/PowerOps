# PO039: Flow is scheduled about every 90 days or less often

Severity: warning

## What it finds

A trigger of type `Recurrence` in a cloud flow whose literal frequency and interval make a run about every 90 days or less often: Day with an interval of 90 or more, Week 13, Month 3, Hour 2,160, Minute 129,600, Second 7,776,000. There is one finding per trigger, naming the flow and the trigger.

The rule reads only Recurrence triggers with a literal frequency and a literal interval. It stays quiet on any other frequency, an interval that is an expression or missing, an interval of 0 or less, and a `recurrence` block under a trigger of another type. It does not read the start time or the schedule's hours and days, and it gives no note for a value it can't read.

## Why it matters

Learn says a cloud flow that isn't triggered within a 90-day period might be turned off. Owners of the flow are told 30 days before. A flow whose only trigger is a Recurrence every 90 days or more is, at the limit, never triggered within some 90-day window, so the service may turn it off, and the scheduled work stops without an error.

Learn also exempts flows whose owners have a premium licence or a capacity licence (Process, per flow) from the turn-off. The rule can't see licences, so it reports the flow either way.

## How to fix

Trigger the flow at least every 90 days, for example a weekly or monthly Recurrence that checks whether the quarterly work is due. Or give the flow an owner with a premium or Process (per flow) licence, which Learn exempts from the turn-off.

To accept the finding for now, run `powerops baseline` and use `powerops analyze --baseline powerops-baseline.json`. A baselined finding is matched on solution, rule, component and message.
