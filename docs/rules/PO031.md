# PO031: Agent has more than 30 tools

Severity: warning

## What it finds

A Copilot Studio agent has more than 30 tools. There is one finding per agent, named by the agent's schema name, with the count in the message.

A tool is a Topic (V2) component (`componenttype` 9 in `botcomponents/<schema>/botcomponent.xml`, whose `parentbotid` names the agent) whose `data` has `kind: TaskDialog`. A connected agent (`action.kind: InvokeConnectedAgentTaskAction`) is not counted: Copilot Studio adds it as an agent, not a tool. Each MCP server counts as one tool, though it publishes tools of its own, so the count is a lower bound. Tools a child agent uses are counted with the agent's: every component, a child agent's tools included, names the root agent in `parentbotid`, and a child agent (`AgentDialog`) names its tools only in its instructions text. Tools of component collections are not read. The schema in microsoft/vscode-copilotstudio documents `TaskDialog.triggerCondition` and an MCP server's `knownTools`; neither was seen in an export, and neither is read.

It reads only agents on the standard harness, as [PO027](PO027.md) describes; any other agent gets PO027's `note:` line. A tool file whose YAML keys PowerOps can't map isn't read either, and PO027's `note:` names it. An agent with 30 or fewer tools and at least one MCP server is "not checked", with one `note:` line on stderr that changes no exit code: `PO031 not checked for agent '<agent>': it has at least one MCP server, and the exports read here don't list the tools an MCP server publishes.` Learn says each tool an MCP server publishes is available to the agent and changes with the server.

The shapes come from public exports in microsoft/CopilotStudioSamples and microsoft/vscode-copilotstudio, not from an export of a Copilot Studio environment.

## Why it matters

Learn says the orchestrator supports up to 128 tools per agent with generative orchestration, and that for best performance and results an agent should have 25 to 30. Learn gives each child agent its own limit, but in an export a child agent's tools still belong to the root agent, so moving them to a child agent doesn't lower this count.

## How to fix

Remove tools the agent doesn't need.

## Suppress

To accept the finding for now, run `powerops baseline` and use `powerops analyze --baseline powerops-baseline.json`. A baselined finding is matched on solution, rule, component and message.
