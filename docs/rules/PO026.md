# PO026: Code app depends on a table or connector that is not in the solution

Severity: warning

## What it finds

A code app (a canvas app whose metadata has `CanvasAppType` 4) names a table or a connector in its `CdsDependencies` that is neither in this solution nor declared as provided by a dependency. There is one finding per app and table or connector, named by the table or connector. Names are compared ignoring case.

The rule reads the app's metadata: `CanvasApps/<name>.meta.xml` in an unpacked folder, a `CanvasApp` element of `customizations.xml` in a zip. In its `CdsDependencies`, an entry with `componenttype` 1 is a table and one with `componenttype` 372 a connector, each named by its `logicalname`. An entry with `componenttype` 29 is a workflow and is not checked.

A table is held when the solution lists it as a root component of type 1 in `solution.xml`, and a connector when it is a root component of type 372. Either is held when a `MissingDependency` in `solution.xml` names it as required. A table whose name has no customization prefix (no underscore), such as `systemuser` or `team`, is not checked: standard tables are part of the system solution and every environment is expected to have them. Dynamics 365 app tables without a prefix, such as `incident`, are not checked either, though an environment without that app doesn't have them.

The rule says "not checked" with one `note:` line on stderr, which changes no exit code, in two cases:

- The app has no `CdsDependencies`, or it isn't a JSON object with a `cdsdependencies` array of entries that each have an integer `componenttype` and, for a table or connector, a `logicalname`. The app gets no finding: `PO026 not checked for code app '<app>': its CdsDependencies is missing or not in a shape PowerOps reads.` The input it needs is that field in that shape.
- An entry has a type other than 1, 372 or 29, such as a connection reference. The app's tables and connectors are still checked, and the note names the other types, at most five and then how many more: `PO026 not checked for code app '<app>': its CdsDependencies has entries of other component types (<n>, <m>), which are not checked.`

The rule doesn't read `DatabaseReferences`. In the public exports its tables are also in `CdsDependencies`, and one export lists a data source there, with the entity set `Environment`, that is not a table the solution could hold. It doesn't read the YAML layout, which Learn says code apps don't support.

Learn says what `CanvasAppType` 4 means and that `CdsDependencies` is for internal use; it doesn't document the field's shape. Learn also lists a `CanvasAppSubtype` column for code apps, which none of the exports below carries, so the rule keys on `CanvasAppType` 4, which all of them have. The shape comes from three code app solutions in public exports: Microsoft's Release Planner (microsoft/PowerAppsCodeApps), the agentic business process sample (microsoft/copilot-agentic-business-process) and the TALXIS warehouse sample (TALXIS/docs-patterns-practices). None of them declares a connector as a missing dependency, so that case rests on PowerOps's own tests. A code app has not yet been taken through `pac solution unpack` in a Dev environment for PowerOps, so the check rests on those exports.

## Why it matters

Learn says importing a solution fails if it doesn't include all required components and the target environment doesn't already have them, and code apps move between environments in solutions, with Pipelines checking dependencies before a deploy. A code app that depends on a table or a custom connector the solution doesn't carry may work where it was built and fail to import where that component isn't. Microsoft's code apps repository has an issue (#342) where stale names in an app's `cdsdependencies` failed a pipeline deploy; the names there were connection references, which this rule reports as not checked.

A solution whose tables sit in another solution, with no declared dependency, gets this warning even when a package always imports the other solution first, because the solution doesn't say so. The TALXIS sample's code app solution is built that way.

## How to fix

Add the table or connector to the solution, or add the solution that holds it as a dependency.

## Suppress

To accept the finding for now, run `powerops baseline` and use `powerops analyze --baseline powerops-baseline.json`. A baselined finding is matched on solution, rule, component and message.
