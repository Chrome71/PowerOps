# PO029: Agent authentication is None

Severity: warning

## What it finds

A Copilot Studio agent's authentication is None. There is one finding per agent, named by the agent's schema name.

The rule reads `authenticationmode` in the agent's `bots/<schema>/bot.xml`, the same path in an unpacked folder and in a zip. Learn's bot table gives its values: 0 Unspecified, 1 None, 2 Integrated, 3 Custom Entra ID and 4 Generic OAuth2. Only 1 is a finding.

It reads only agents on the standard harness, as [PO027](PO027.md) describes; any other agent gets PO027's `note:` line. It says "not checked" with one `note:` line on stderr, which changes no exit code, when `bot.xml` has no `authenticationmode` or it isn't an integer: `PO029 not checked for agent '<agent>': its bot.xml has no authenticationmode.`

## Why it matters

Learn says that with No authentication anyone who has the link can chat and interact with the agent, and that the agent can only access public information. Copilot Studio's security scan warns makers before publishing when an agent is set to No authentication. An agent meant for an organization or for specific users needs a sign-in.

## How to fix

Set the agent's authentication to Authenticate with Microsoft or Authenticate manually.

## Suppress

To accept the finding for now, run `powerops baseline` and use `powerops analyze --baseline powerops-baseline.json`. A baselined finding is matched on solution, rule, component and message.
