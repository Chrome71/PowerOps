# PO038: Flow action has its static result turned on

Severity: warning

## What it finds

An action of a cloud flow whose `runtimeConfiguration.staticResult.staticResultOptions` is `Enabled`, at any depth. There is one finding per action, naming the flow and the action. An action with the option `Disabled` or without the setting is not reported.

## Why it matters

Learn says an action with its static result on is treated as successful without running. A flow that ships with it on skips that action after deployment, and the rest of the flow carries on as if it had run.

The flow definition keeps the setting in `runtimeConfiguration.staticResult`, which names an entry of the definition's `staticResults`. Learn shows the value `Enabled` only, so the rule fires on that value. That an export keeps the setting is not on Learn: it was observed in the second export of the m58 capture, where the action's static result stayed in the exported solution.

## How to fix

Turn off the action's static result before you export, so the action runs instead of returning test output. If the action should stay mocked, test with a flow test of PowerOps instead, which does not change the exported flow.

## Suppress

To accept the finding for now, run `powerops baseline` and use `powerops analyze --baseline powerops-baseline.json`. A baselined finding is matched on solution, rule, component and message.
