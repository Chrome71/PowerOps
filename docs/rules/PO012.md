# PO012: Dataverse row-updated trigger has no filter columns

Severity: warning

## What it finds

A cloud flow starts with the Dataverse "When a row is added, modified or deleted" trigger, the trigger's change type includes Update (Update, Create or Update, Update or Delete, or all three), and no filter columns are set.

## Why it matters

The flow runs on every update of the table, whichever column changed. This wastes runs, can cause loops when the flow itself updates the row, and hits Power Platform request limits.

## How to fix

Set "Select columns" (filter columns) to the columns whose update should start the flow.

Three caveats from Learn. Filter columns apply to the Update condition only; Create and Delete apply to all columns of a row. A lookup column in the filter doesn't start the flow when it changes, so don't choose one. And don't choose a column that is in every update request, like the primary key, because the flow runs whenever a listed column is in the request, even if its value didn't change.

Don't set filter columns on a trigger whose change type is Create only; see [PO015](PO015.md).
