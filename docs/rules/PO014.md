# PO014: Canvas app formula contains a hard-coded environment or SharePoint site URL

Severity: warning

## What it finds

A canvas app property formula (a value that starts with `=`) in the app's `Src/*.pa.yaml` source contains a literal Dataverse environment URL (`https://contoso.crm.dynamics.com`) or SharePoint site URL (`https://contoso.sharepoint.com/sites/team`). Only these patterns are matched, the same as PO006, so public links are ignored. Each distinct URL per app is one finding, naming the first control and property where it appears.

The source is read from the `Src` folder of the Dataverse Git integration YAML layout, and, in the unpacked XML and zip layouts, from inside each `CanvasApps/*.msapp`, which is a zip that holds the same `Src/*.pa.yaml` files. The [PO018](PO018.md) page says where Learn puts them. The `.msapp` is read in memory, nothing is written to disk, and only the `Src/*.pa.yaml` entries are opened. The finding's file is the `.msapp` path.

When no `Src/*.pa.yaml` is read from an `.msapp`, the rule gives no finding: the `.msapp` has no `Src` folder, or it isn't a zip (no `PK` signature, as with an empty file or a Git LFS pointer) and isn't opened. A zip that fails to open, or one that is over a read limit, stops the command as a malformed file does. Instead `analyze` prints one `note:` line on stderr per app and the exit code doesn't change: `PO014 and PO018 not checked for canvas app '<file>': no Src/*.pa.yaml was read from its .msapp (an older app has none until it is resaved in Studio, and a file that isn't a zip, such as a Git LFS pointer, is not opened).` The input it needs is the app's `.msapp` with its `Src` folder. An app whose `.msapp` the solution doesn't hold, for example a repo that drops it because it caches the environment URL (this repo's `powerops-seed` fixture leaves it out for that reason, see `tests/fixtures/NOTICE.md`), isn't read and gets no note.

## Why it matters

The URL points at one environment or site, so the app keeps calling the source environment or site after the solution is imported into another environment.

## How to fix

1. Do not use a URL where the platform can use the current environment. For a canvas app, use Dataverse in the current environment: Microsoft's overview says you do not need an environment variable for tables in your current environment.
2. Otherwise use an environment variable. Leave its default value empty, because a URL default triggers PO007, and keep no current value in the solution, because a shipped current value triggers PO008. Set the value for each environment when the solution is imported, through a deployment settings file or Pipelines. A required variable that has no value triggers PO002.
3. For a URL inside a canvas formula, read the variable's value from the Environment Variable Definition and Environment Variable Value tables (named in Microsoft's overview) through the Dataverse connector. Microsoft's environment variables FAQ names using the Dataverse connector to read environment variables as the one licensing caveat for premium connectors, and calls it the earlier route for canvas apps and flows.
4. For a SharePoint data source (not a URL in a formula), bind its site and list to data source environment variables.
5. For relational configuration data, use other tools such as the Configuration migration utility instead of environment variables, as Microsoft's environment variables FAQ advises. Never hard-code the URL.

## Suppress

To accept the finding for now, run `powerops baseline` and use `powerops analyze --baseline powerops-baseline.json`. A baselined finding is matched on solution, rule, component and message.
