# PO019: Power Pages Web API fields setting is *

Severity: warning

## What it finds

A site setting `Webapi/<table>/fields` whose whole value, trimmed, is `*`, in a site that also has `Webapi/<table>/enabled` set to `true` for the same table. There is one finding per such setting, named by the setting's name.

Only active site settings (component type 9) count. Setting names are compared ignoring case, and both settings must belong to the same site. `enabled` is on when its value, trimmed, is `true` in any case. With `enabled` false or missing the rule is quiet, because Learn gives `enabled` a default of `False`.

Only a whole value of `*` counts. Learn's examples are all a whole `*`, and it doesn't say whether `*` as one entry of a list, such as `name,*`, is a wildcard, so the rule doesn't guess.

The rule reads the `powerpagecomponents/` folder of the enhanced data model in a solution, unpacked or in a zip. It does not read the `.powerpages-site/` layout. Learn doesn't document the export layout; the `value` key in a site setting's `content` was observed in the core-portal solution of microsoft/gov-apptemplates and in the Contoso Real Estate sample.

## Why it matters

Learn says support for `*` in this setting is deprecated. From August 2026 new sites can't use it, and from 14 September 2026 requests to a table configured with `*` fail until the setting lists columns. Learn gives the reason as least privilege: `*` makes every column of the table available through the Web API.

An admin can request one extension per site in the Power Platform admin center. Learn lists 90 days for this change, says an extension can't be renewed, and says enforcement is deferred on the site until it ends. That is why this rule is a warning and not an error: a site with an extension still works with `*` for now.

## How to fix

Replace `*` with the comma-separated logical names of the columns the site needs. Learn says to look at response properties, create and update payloads, and `$select`, `$filter`, `$orderby` and `$expand`, and not to add every column as a replacement. Or set `Webapi/<table>/UseFieldsFromView` to `True` and put the columns in a public system view of the table named Power Pages Web API Columns. If both are set, Learn says the Web API combines them. Learn says `UseFieldsFromView` is available in site version 9.8.8.x and later. An export doesn't show the site's version (the site record in the core-portal solution holds none), so the rule can't check it.

Microsoft's own sample sites trip some of the Power Pages rules, so the message says "before Production", not "now". The Contoso Real Estate sample sets `*` on three tables.

To accept the finding for now, run `powerops baseline` and use `powerops analyze --baseline powerops-baseline.json`. A baselined finding is matched on solution, rule, component and message.
