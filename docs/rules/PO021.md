# PO021: Power Pages table permission has no web role

Severity: warning

## What it finds

An active table permission (component type 18) that lists no web role in `adx_entitypermission_webrole` (missing, null or empty) and has no parent permission. There is one finding per permission, named by the permission's name. A listed role counts whether or not the solution holds that web role.

A child permission, one with `parententitypermission` set, is never a finding here. With no roles of its own it takes its parent's roles, so the parent's roles are the ones that matter. PO022 checks a child against its parent.

The rule reads the `powerpagecomponents/` folder of the enhanced data model in a solution, unpacked or in a zip. It does not read the `.powerpages-site/` layout. Learn doesn't document the export layout; the `adx_entitypermission_webrole` key, with the role ids, was observed in the table permissions of the Contoso Real Estate sample.

## Why it matters

Learn says a table permission takes effect only when it is associated with one or more web roles, and that users in those roles get its privileges. A permission with no role gives no access. Design studio shows a message when you try to save one. Learn's security advice includes deleting permissions that are no longer needed.

## How to fix

Associate the table permission with the web roles that need it, or delete it. Learn says deleting a table permission deletes its child permissions too.

Microsoft's own sample sites trip some of the Power Pages rules, so the message says "before Production", not "now".

## Suppress

To accept the finding for now, run `powerops baseline` and use `powerops analyze --baseline powerops-baseline.json`. A baselined finding is matched on solution, rule, component and message.

Two permissions with the same name and table give findings that differ only in their file, so one baseline entry covers both.
