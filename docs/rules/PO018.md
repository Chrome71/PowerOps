# PO018: Canvas app formula calls Patch or ForAll inside ForAll

Severity: warning

## What it finds

A canvas app property formula (a value that starts with `=`) that calls `Patch` inside a `ForAll`, as in `ForAll(items, Patch(source, ...))`, or calls `ForAll` inside a `ForAll`. A call counts anywhere between the parentheses of the outer `ForAll`, as an argument of another function such as `If` too. A formula gets at most one finding per kind, naming the first control and property: `Patch` inside `ForAll`, then `ForAll` inside `ForAll`.

The rule is a token scan, not a Power Fx parser. It matches `ForAll` and `Patch` ignoring case, and skips text inside strings, single-quoted names and comments. Three limits follow. A `Patch` inside a user-defined function that the `ForAll` calls is not seen. An interpolated string (`$"...{Patch(...)}..."`) is skipped whole, so a call inside it is missed. A call in the `ForAll`'s table argument, `ForAll(Patch(...), ...)`, counts as inside the `ForAll`. The rule also can't tell whether the `Patch` target is a collection or a data source, so a finding on a collection can be baselined.

The formulas come from the app's `Src/*.pa.yaml` source: the `Src` folder in the Dataverse Git integration YAML layout, and, in the unpacked XML and zip layouts, the `Src` folder inside each `CanvasApps/*.msapp`. Learn says Studio stores the source files in the `.msapp`'s `\Src` folder, and that an older `.msapp` without it must be imported, resaved and downloaded again. The `.msapp` is read in memory, nothing is written to disk, and only the `Src/*.pa.yaml` entries are opened.

When no `Src/*.pa.yaml` is read from an `.msapp`, the rule gives no finding: the `.msapp` has no `Src` folder, or it isn't a zip (no `PK` signature, as with an empty file or a Git LFS pointer) and isn't opened. A zip that fails to open, or one that is over a read limit, stops the command as a malformed file does. Instead `analyze` prints one `note:` line on stderr per app and the exit code doesn't change: `PO014 and PO018 not checked for canvas app '<file>': no Src/*.pa.yaml was read from its .msapp (an older app has none until it is resaved in Studio, and a file that isn't a zip, such as a Git LFS pointer, is not opened).` PO014 shares the note, and `<file>` is the `.msapp` path in the solution. The input it needs is the app's `.msapp` with its `Src` folder. An app whose `.msapp` the solution doesn't hold, for example a repo that drops it because it caches the environment URL, isn't read and gets no note.

## Why it matters

Learn says to avoid nesting `ForAll`, which can lead to exponential iterations. It also says `Patch(source, ForAll(...))` is the better approach and `ForAll(..., Patch(...))` is less efficient.

## How to fix

Pass the `ForAll` result to one `Patch` call, `Patch(source, ForAll(...))`, instead of calling `Patch` inside `ForAll`. Don't nest `ForAll`; compute the inner set once, outside the outer loop, or reshape the data so one pass is enough.

If a nested loop can't be avoided, keep it and baseline the finding as Suppress says.

## Suppress

To accept the finding for now, run `powerops baseline` and use `powerops analyze --baseline powerops-baseline.json`. A baselined finding is matched on solution, rule, component and message.
