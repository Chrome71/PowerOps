# PO025: Model-driven app has more than 25 custom pages, 10 connectors or 20 connection references

Severity: warning

## What it finds

A model-driven app with more than 25 custom pages, or whose custom pages together use more than 10 connectors or more than 20 connection references. Each limit gives its own finding, named by the app's unique name:

- `App '<app>' has <n> custom pages, more than 25.`
- `The custom pages of app '<app>' use <n> connectors, more than 10.`
- `The custom pages of app '<app>' use <n> connection references, more than 20.`

An app's custom pages are the pages its app module lists (`appelements`) and the `Page` targets of the site maps it names, each counted once, by name ignoring case. An app module lists the component libraries its pages use as `appelements` too; one whose metadata in the solution has `CanvasAppType` 1 (Learn: App Component Library), or any type other than 2 (Custom Canvas Page), is not counted. One whose metadata isn't in the solution, or has no `CanvasAppType`, is counted, since its type can't be read. Connectors and connection references are read from each page's `ConnectionReferences` metadata: the connectors are the distinct connector ids (`id`), and the connection references are the distinct entries, by key, across all the app's pages, so a connection that two pages share counts once. Learn gives the limits across all custom pages but doesn't say how to count them from an export; this count is PowerOps's reading of the metadata observed in Microsoft's public exports (microsoft/gov-apptemplates), where pages share entries and an app lists a component library among its `appelements`.

A page whose metadata the solution doesn't hold, or whose `ConnectionReferences` isn't a JSON object, still counts as a page, but its connections are not checked. `analyze` prints one `note:` line per app on stderr and the exit code doesn't change: `PO025 not checked for app '<app>': <n> of its custom pages have no readable metadata in the solution, so their connectors and connection references are not counted.` The input it needs is each page's canvas app metadata (`CanvasApps/<name>.meta.xml`, or the `CanvasApp` element of a zip's `customizations.xml`).

Learn says an app can have its own site map, and every export PowerOps has read names one per app. An app module that names more than one site map in the solution is counted with only the first, by name in ordinal order, and gets a note: `PO025 not checked for app '<app>': it names <n> site maps in the solution, and only '<first>' is counted.` A site map the app names that isn't in the solution gives a note too, since the pages it opens can't be counted: `PO025 not checked for app '<app>': its site map '<name>' is not in the solution, so the custom pages it opens are not counted.`

The rule reads `AppModules/<name>/AppModule.xml` and `AppModuleSiteMaps/<name>/AppModuleSiteMap.xml` in an unpacked folder (or the `_managed` file when there is no other), and the `AppModule` and `AppModuleSiteMap` elements of a zip's `customizations.xml`. It does not read the YAML layout. The `appelements` list, the site map named as a `type="62"` app module component and the `Page` attribute were observed in Microsoft's Creator Kit reference app (microsoft/powercat-creator-kit), whose 27 custom pages would give one finding.

## Why it matters

Learn says not to exceed 25 custom pages in a model-driven app: more increase the wait on the first launch after each publish. It says the connectors across all custom pages shouldn't exceed 10 and the connection references 20, since more increase the wait when a user plays the app, and that when an app has several custom pages, the consent dialog asks for permission for the connectors of all of them, even pages not yet opened.

## How to fix

Move custom pages to another app, or remove pages and connections, until the app has at most 25 custom pages, 10 connectors and 20 connection references.

## Suppress

To accept the finding for now, run `powerops baseline` and use `powerops analyze --baseline powerops-baseline.json`. A baselined finding is matched on solution, rule, component and message. The message holds the count, so a baselined finding comes back when the count changes, as with PO016.
