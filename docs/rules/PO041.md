# PO041: Text environment variable looks like it holds a secret

Severity: warning

## What it finds

An environment variable of type Text (the Dataverse value `100000000`, called String there) whose schema name contains, ignoring case, one of `secret`, `password`, `pwd`, `token`, `apikey`, `api_key` or `connectionstring`, and does not end, ignoring case, in `name`, `id`, `url`, `uri`, `ref`, `reference`, `path`, `date`, `expiry` or `expiration`. A name such as `demo_SecretName` holds a secret's name, not the secret. There is one finding per variable, naming it.

The rule reads the type and the schema name only. It never reads or prints a value, neither the default nor the current one. Variables of any other type, a Secret variable included, are not reported.

This is a name heuristic, so it has known edges. `demo_TokenEndpoint` and `demo_SecretVersion` fire, although they probably hold no secret. `demo_PasswordValid` is quiet, because its name ends in `id`. Accept a finding that is wrong with `powerops baseline`.

## Why it matters

The value of a Text variable is plain text in the solution and the settings files. The solution export holds a Text variable's default value as written. That was observed in exported fixtures; it is not stated on Learn. `PO008` reports a current value that ships in the solution.

Learn says a Text variable that holds a custom connector's client secret isn't secure and its values are not encrypted, and recommends Azure Key Vault. No Learn page says so for Text variables in general. The Secret type reads its value from Azure Key Vault.

## How to fix

Make it an environment variable of type Secret backed by Azure Key Vault, and remove its value from the solution and the settings files. The Dataverse table reference also lists a Dataverse secret store; this page names Key Vault, the store that the maker page documents.
