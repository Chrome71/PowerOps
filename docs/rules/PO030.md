# PO030: Agent tool uses the maker's credentials

Severity: warning

## What it finds

A Copilot Studio agent's tool uses the maker's credentials: its `data` has `action.connectionProperties.mode` set to `Maker`, compared ignoring case. There is one finding per tool, named by the tool's schema name.

A tool is a Topic (V2) component (`componenttype` 9 in `botcomponents/<schema>/botcomponent.xml`, whose `parentbotid` names the agent) whose `data` has `kind: TaskDialog`. A tool with no `connectionProperties`, such as a flow, or with `mode: Invoker`, is quiet; Learn says end-user credentials are the default.

It reads only agents on the standard harness, as [PO027](PO027.md) describes; any other agent gets PO027's `note:` line, and its tools are not checked. A tool file whose YAML keys PowerOps can't map isn't read either, and PO027's `note:` names it.

Learn says agents with event triggers use only the maker's credentials, and tools called in response to a trigger must too. Which tools a trigger calls isn't in the export, so such tools get this warning; accept them with a baseline when that is the design.

The shapes come from public exports in microsoft/CopilotStudioSamples and microsoft/vscode-copilotstudio, not from an export of a Copilot Studio environment.

## Why it matters

With maker-provided credentials, the agent uses the maker's account, not the user's, to reach the connected service, so a user may retrieve information or do things that only the maker's account is permitted to do. Copilot Studio's security scan warns makers before publishing when a connector or flow uses maker-provided credentials, and admins can turn the option off for an environment, which then makes every such tool ask users to sign in.

## How to fix

Set the tool to use end-user credentials, unless every user may act with the maker's permissions or a trigger calls the tool.

To accept the finding for now, run `powerops baseline` and use `powerops analyze --baseline powerops-baseline.json`. A baselined finding is matched on solution, rule, component and message.
