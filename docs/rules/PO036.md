# PO036: Canvas app repeats the same formula in three or more places

Severity: warning

## What it finds

A canvas app that holds the same property formula (a value that starts with `=`) in three or more places. A place is one control and property, such as `btnOpen.OnSelect`. There is one finding per app and repeated formula. Its message gives the app, the number of places and the first three of them, in ordinal order of `Control.Property`; with three places the `and <n> more` part is left out. The finding's component is the first place, and its file is the file that place was read from:

- `Canvas app '<app>' has the same formula in <count> places (<place>, <place>, <place>, and <n> more); a change must be made in each.`

The message never holds the formula's text, because a formula can hold values of a tenant. Open the first place in Studio to read it.

Two formulas are the same when their text is equal after the leading `=` is dropped, every run of whitespace (spaces, tabs, line breaks) is made one space and the ends are trimmed. Case is kept, so `varNote` and `VarNote` differ. Only formulas of 80 characters or more, counted on that text, are compared. A place that the source lists twice counts once. Places in two apps are never counted together; an app is its folder in the solution, not its display name, because two apps can share a display name.

The two thresholds, 80 characters and three places, are PowerOps's own choice and not Microsoft's: Learn gives no number for either. They keep short repeats such as `Parent.Width` or `ThisItem.Title`, and a formula that is in only two places, quiet.

The rule compares text and is not a Power Fx parser. Two limits follow. Formulas that differ in a name, a literal or the spacing around an operator (`a+b` and `a + b`) are not the same to it, so a near copy is missed. Whitespace inside a string or a comment is collapsed like any other, so two formulas that differ only there count as the same.

The formulas come from the app's `Src/*.pa.yaml` source, read as the [PO018](PO018.md) page says. When no `Src/*.pa.yaml` is read from an `.msapp`, the rule gives no finding, and `analyze` prints the `note:` line it shares with PO014 and PO018, one per app: `PO014, PO018 and PO036 not checked for canvas app '<file>': no Src/*.pa.yaml was read from its .msapp (an older app has none until it is resaved in Studio, and a file that isn't a zip, such as a Git LFS pointer, is not opened).` The input it needs is the app's `.msapp` with its `Src` folder. An app whose `.msapp` the solution doesn't hold isn't read and gets no note.

## Why it matters

Learn says that copying and pasting a control with a long formula duplicates the formula in the control's properties without anyone noticing, and that when one formula appears in many places it becomes "tedious and error prone to update" them all when a change is needed. Each copy has to be found and changed by hand.

## How to fix

Define the formula once and use its name in each place. Learn names these ways:

1. A named formula in `App.Formulas`, for a calculation. Learn says a named formula can replace a calculation anywhere in an app, and that it can't use behavior functions or cause side effects.
2. A user-defined function in `App.Formulas`, when the copies need a parameter. Learn says a behavior user-defined function, whose body is in curly braces, can hold behavior logic such as `Set` or `Notify`.
3. A canvas component with a custom output property, as an alternative to a named formula.
4. For imperative logic on one screen, the `OnSelect` of a hidden button, run from each place with `Select`.

If the copies are meant to stay apart, keep them and baseline the finding as Suppress says.

## Suppress

To accept the finding for now, run `powerops baseline` and use `powerops analyze --baseline powerops-baseline.json`. A baselined finding is matched on solution, rule, component and message.
