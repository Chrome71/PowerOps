# PO040: Approval can wait as long as a run can last

Severity: warning

## What it finds

An approvals wait action in a cloud flow whose `limit.timeout` is an ISO 8601 duration of 30 days or more. The wait actions are the Approvals connector's `StartAndWaitForAnApproval`, `WaitForAnApproval`, `StartAndWaitForATextSuggestionApproval`, and the deprecated `approvalSubscribe` and `approvalSubscribeV2`. There is one finding per action, naming the flow, the action and the whole days.

The rule leaves alone: an approval with no timeout (that is the designer's default, and the rule does not report it), a timeout under 30 days, a negative duration, an action that only creates the approval (`CreateAnApproval`), and any other action with a timeout, such as an Until loop.

A month in a duration reads as 30 days and a year as 365 days, so `P1M` and `P1Y` are reported. The week form (`P5W`), lower case (`p30d`), an expression and a value too large to read are not durations this rule reads: they give the note below and no finding.

## Why it matters

Learn's limits page says a run lasts at most 30 days, pending approvals included, after which pending steps time out. An approval whose timeout is 30 days or more therefore can run past the end of the run, and the pending step times out with the run, not at the time the timeout says. The rule's line is 30 days, the figure of the limits page. The Learn page of known issues for approvals gives 28 days as how long an approval flow can wait, so a timeout under 28 days is the safest, and the Fix below stays true for it.

## How to fix

Set the approval's timeout under 30 days (under 28 is safest) and handle its expiry, for example with a branch on the action's failed or timed-out result. Or create the approval in one flow (Create an approval) and act on the response in a second flow that the response triggers, so no run waits for the whole period.

## Not checked

The timeout of an approval can be an expression or a value that is not an ISO 8601 duration this rule can read. Then it gives no finding, and `analyze` prints the note "PO040 not checked for flow '<flow>': approval '<action>' has a timeout this rule can't read as a duration." naming the flow and the action. The rule reads the timeout from the key `limit.timeout` of the exported action. Learn documents that key for the Logic Apps action types, and Power Automate's error-handling guidance says to set the action's Timeout setting as an ISO 8601 duration; no public export of an approval with a timeout was found to confirm that an exported cloud flow holds it under that key. If it holds it elsewhere, the rule stays quiet: it can miss a finding but doesn't report a false one.
