# PO028: Agent instructions are empty or longer than 8,000 characters

Severity: warning

## What it finds

A Copilot Studio agent's instructions are longer than 8,000 characters, or empty while its generative orchestration is on (`settings.GenerativeActionsEnabled` is `true` in `bots/<schema>/configuration.json`). There is one finding per agent, named by the agent's schema name.

The rule reads the agent's Custom GPT component (`componenttype` 15 in `botcomponents/<schema>/botcomponent.xml`, whose `parentbotid` names the agent) and the top-level `instructions` of its `data`. A missing `instructions` key, an empty value and a value of only whitespace are empty. Characters are counted after trailing line breaks are removed, since a YAML block scalar keeps line breaks the maker didn't type, and as UTF-16 code units, so a character outside the Basic Multilingual Plane, such as most emoji, counts as two.

Empty instructions are quiet when generative orchestration is off or the configuration doesn't say: Learn says that with classic orchestration an agent calls tools only from topics, so there is nothing for instructions to steer.

It reads only agents on the standard harness, as [PO027](PO027.md) describes; any other agent gets PO027's `note:` line. It says "not checked" with one `note:` line on stderr, which changes no exit code, when the agent has no Custom GPT component with a `data` file, has more than one, has `instructions` that aren't text, or has a `data` file whose keys PowerOps can't map (an empty key, a key that isn't text, or an `@` or `#text` key whose value isn't text): `PO028 not checked for agent '<agent>': it has no single Custom GPT component whose instructions are text.`

The shapes come from public exports in microsoft/CopilotStudioSamples and microsoft/vscode-copilotstudio and from a local `pac copilot init` and `pac copilot pack`, not from an export of a Copilot Studio environment. An agent that `pac copilot init` scaffolds has empty instructions until they are written. Of the five standard-harness agents in the public samples read for this rule, all with generative orchestration on, three have empty instructions and get this warning; accept it with a baseline when that is the design.

## Why it matters

Learn says an agent's instructions can have up to 8,000 characters, and that editing them changes how the agent engages with users. With generative orchestration, instructions shape how the agent selects and uses its topics, tools, other agents and knowledge, and an agent with none has nothing that does.

## How to fix

Write the agent's instructions, in at most 8,000 characters.

To accept the finding for now, run `powerops baseline` and use `powerops analyze --baseline powerops-baseline.json`. A baselined finding is matched on solution, rule, component and message.
