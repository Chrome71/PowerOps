# PO024: Site map opens a custom page that is not in the solution

Severity: error

## What it finds

A model-driven app's site map has a `SubArea` whose `Page` attribute names a custom page that is neither a canvas app in this solution (its metadata, or a type 300 root component in `solution.xml`) nor declared as provided by a dependency (a `MissingDependency` in `solution.xml` whose required component has that name). There is one finding per site map and page, named by the page. Names are compared ignoring case.

A custom page is a canvas app, and its name is the `Name` in its metadata: `CanvasApps/<name>.meta.xml` in an unpacked folder, a `CanvasApp` element of `customizations.xml` in a zip. A `SubArea` is read at any depth under `SiteMap`. One with an `Entity` attribute is a table entry, even if it also has `Page`, and is not checked: it points at a table, and tables such as `systemuser` exist in every environment.

The rule says "not checked" in two cases, with one `note:` line on stderr, no finding and no exit-code change:

- The solution holds no canvas app metadata at all, so it can't tell a missing page from a folder that left `CanvasApps/` out: `PO024 not checked for site map '<sitemap>': custom page '<page>' is not in the solution, and the solution holds no canvas apps to check it against.` The input it needs is the canvas app metadata of the solution.
- A `SubArea` with a `GenPageId` attribute opens a generative page. Its page lives under `uxagentprojects/`, which PowerOps doesn't read yet, because no export has been seen to carry it: `PO024 not checked for site map '<sitemap>': generative page '<id>' is not checked, because uxagentprojects/ is not read.` A generative page id declared as a dependency gives no note.

The rule reads the `AppModuleSiteMaps/<name>/AppModuleSiteMap.xml` files of an unpacked folder (or the `_managed` file when there is no other) and the `AppModuleSiteMap` elements of a zip's `customizations.xml`. It does not read the YAML layout. Learn doesn't document the export layout. The `Page` attribute holding the canvas app's name was observed in Microsoft's Creator Kit reference app (microsoft/powercat-creator-kit), the zip mapping in a local `pac solution pack` of the `alm-sample` fixture, and the `GenPageId` attribute and the order `GenPageId`, `Entity`, `Page` in Microsoft's power-platform-skills source.

## Why it matters

Learn says each custom page is a separate solution component, added to an app's site map in the app designer, and that importing a solution fails if it doesn't include all required components and the target environment doesn't already have them. A site map entry for a page the solution doesn't carry works in the environment it was built in and may break where the page isn't.

The rule takes a page as held when the solution has its metadata, lists it as a root component (type 300), or declares it as a missing dependency. It rests on the export declaring a page that is outside the solution. That is how exports declare other canvas apps outside the solution: Microsoft's Creator Kit export lists the component library its pages need, which is outside the solution, as a `Required` node of type 300 with its `schemaName`. No public export was found whose site map opens a page outside the solution, so if your export doesn't declare such a page, PO024 fires on it. Add the dependency, or baseline the finding.

## How to fix

Add the custom page to the solution, or add the solution that holds it as a dependency. If the entry is no longer needed, remove it from the site map in the app designer.

## Suppress

To accept the finding for now, run `powerops baseline` and use `powerops analyze --baseline powerops-baseline.json`. A baselined finding is matched on solution, rule, component and message.
