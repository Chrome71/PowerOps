# PO015: Dataverse row-created trigger has filter columns

Severity: error

## What it finds

A cloud flow starts with the Dataverse "When a row is added, modified or deleted" trigger, the trigger's change type is Create only, and filter columns ("Select columns") are set.

## Why it matters

In observed runs, a flow like this never started. Learn says filter columns apply to the Update condition only, and that Create and Delete apply to all columns of a row. It doesn't say that setting them on a Create-only trigger stops the flow. The result comes from two runs in one environment, one on Windows on 2026-10-30 and one on Linux on 2026-10-31:

- In both runs, a Create-only flow with filter columns did not run when a row was created.
- In the Linux run, taking the filter off with a save made the flow run on the next new row. A flow turned on with filter columns had no row in the `callbackregistrations` table until that save, and one appeared within seconds of it.
- In the Linux run, a Create-only flow without filter columns ran, and so did a Create or Update flow with filter columns, on a new row.

The rule is an error because the flow doesn't run. It rests on those runs, not on anything Learn states, and Microsoft can change the behavior. What was not tested: a Delete-only trigger and a Create or Delete trigger, which the rule leaves alone; a managed solution; and a production environment. The cause on the service's side isn't known: `callbackregistrations` showed the difference, but nothing shows why.

## How to fix

Clear the trigger's filter columns, or change its change type to Create or Update. Filter columns work on an update, so use them with a change type that includes Update, as [PO012](PO012.md) describes.
