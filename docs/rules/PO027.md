# PO027: MCP server on an agent with generative orchestration off

Severity: error

## What it finds

A Copilot Studio agent has a Model Context Protocol (MCP) server among its tools, and its configuration has generative orchestration off. There is one finding per MCP server, named by its component's schema name.

The rule reads the agent's `bots/<schema>/configuration.json` and the components of `botcomponents/` whose `parentbotid` names the agent, the same paths in an unpacked folder and in a zip. Generative orchestration is off when `settings.GenerativeActionsEnabled` is `false`. A tool is a Topic (V2) component (`componenttype` 9) whose `data` has `kind: TaskDialog`; it is an MCP server when its `action.operationDetails.kind` is `ModelContextProtocolMetadata`. One such component connects the agent to one server, which publishes its own tools. A tool's `data` file that is valid YAML but whose keys PowerOps can't map (an empty key, a key that isn't text, an `@` key that XML rejects as an attribute, such as `@xmlns` with a reserved namespace, or an `@` or `#text` key whose value isn't text) isn't read, and PO027 prints one `note:` line for it: `PO027 not checked for agent '<agent>': '<file>' is valid YAML whose keys PowerOps can't map, so the tool it may hold isn't read, and PO030 and PO031 don't check it either.`

Which agents: PO027 to PO031 read agents on Copilot Studio's standard harness. An agent is placed there when its `configuration.json` is a JSON object whose `recognizer` names no `$kind`, `GenerativeAIRecognizer` or `VirtualAgentsRecognizer`. Any other agent gets no finding from these rules, and PO027 prints one `note:` line on stderr for it, which changes no exit code:

- `PO027 to PO031 not checked for agent '<agent>': its configuration.json is missing or isn't a JSON object.`
- `PO027 to PO031 not checked for agent '<agent>': its recognizer is '<kind>', not GenerativeAIRecognizer or VirtualAgentsRecognizer, so it may not run on the standard harness that these rules read.`

Learn doesn't say which recognizer each harness writes. Agents that `pac copilot init` makes in its default mode, and the standard agents in public exports, name `GenerativeAIRecognizer`; an agent made with `--authoring-mode cli-copilot` names `CLICopilotRecognizer`, and Microsoft's order-management MCP sample names `CLIAgentRecognizer`. Learn says the GitHub Copilot harness runs on an orchestration runtime that replaces the standard one. The schema in microsoft/vscode-copilotstudio calls `VirtualAgentsRecognizer` the default recognizer, which uses Power Virtual Agents recognition; no export with it was seen, and neither was the recognizer of an agent with classic orchestration, the configuration this rule's finding needs. A recognizer that is there but names no kind is `''` in the note.

The rule also says "not checked" for a placed agent with an MCP server whose configuration has no boolean `GenerativeActionsEnabled`: `PO027 not checked for agent '<agent>': its configuration.json doesn't say whether generative orchestration is on.`

Learn doesn't document `GenerativeActionsEnabled`. Microsoft's MIT-licensed skills for Copilot Studio describe it as the switch that enables generative orchestration, and every public export read for this rule has it `true`; no export with `false` was found, so the firing case rests on PowerOps's own tests. The shapes come from public exports in microsoft/CopilotStudioSamples and microsoft/vscode-copilotstudio and from a local `pac copilot init` and `pac copilot pack`, not from an export of a Copilot Studio environment.

## Why it matters

Learn says generative orchestration must be turned on to use MCP. With classic orchestration an agent calls tools only from topics, so an MCP server on such an agent can't do the job it was added for, and the agent behaves differently in the target environment from what its maker expects.

## How to fix

Turn on generative orchestration for the agent, or remove the MCP server.

## Suppress

To accept the finding for now, run `powerops baseline` and use `powerops analyze --baseline powerops-baseline.json`. A baselined finding is matched on solution, rule, component and message.
