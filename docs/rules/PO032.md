# PO032: Model-driven app is shared only with admin roles

Severity: warning

## What it finds

A model-driven app whose role map names only the System Administrator and System Customizer security role templates. There is one finding per app, named by the app's unique name:

- `App '<app>' is shared only with System Administrator or System Customizer, so users without an admin role may not be able to open it.`

The role map is the app module's `AppModuleRoleMaps`. Each `Role` in it is matched by its `id` against the role template ids that Learn documents, never by name, since a name can be renamed and differs by language. Learn says the template ids are constant in all environments and role ids are not. An app whose role map also holds another documented template (such as Basic User), or the id of a role in the solution, is quiet: it is open to users without an admin role. The 15 other documented templates count as non-admin roles whatever they grant, Support and Proxy included, because Learn doesn't list what each grants; an app also shared with one of them is quiet, which is a missed finding at worst and never a false one. An app with an empty or missing role map is not checked: Learn says only makers open such an app, and this rule is about apps shared with admins alone. The message says "may" because a user can hold Basic User, App Opener or another role beside the ones the app names.

A role map id that is neither a documented template nor the id of a role in the solution may be a custom role from another solution, or Environment Maker, which has no template. When no other id of the app makes it quiet, `analyze` prints one `note:` line per app on stderr, and the exit code doesn't change: `PO032 not checked for app '<app>': <n> of its role map ids are neither a documented role template nor a role in the solution.`

The rule reads `AppModules/<name>/AppModule.xml` and `Roles/<name>.xml` in an unpacked folder, and the `AppModule` and `Role` elements of a zip's `customizations.xml`. It does not read the YAML layout.

Learn's part: the two template ids and that they are constant in all environments, and that System Administrator and System Customizer can open every model-driven app. Observed in exports, not documented: that a role map names a custom role by the `id` of its `Role` element, as in microsoft/powercat-automation-kit, and that it names the two admin templates by their template ids, as in Microsoft's public exports (microsoft/gov-apptemplates, microsoft/Nonprofits and `alm-sample` in this repository).

## Why it matters

Learn says a user who has only the Read privilege on the Model-driven App table must also hold a security role the app is shared with, and that users with only the Basic User role can open only the apps that role is assigned to. System Administrator, System Customizer and Environment Maker can open every app. An app shared only with the two admin roles may therefore not open for the users it was built for.

## How to fix

Share the app with the security roles its users hold, and remove System Administrator and System Customizer from it unless they need the app.
