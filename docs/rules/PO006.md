# PO006: Flow contains a hard-coded environment or SharePoint site URL

Severity: warning

## What it finds

A cloud flow contains a literal Dataverse environment URL (`https://contoso.crm.dynamics.com`) or SharePoint site URL (`https://contoso.sharepoint.com/sites/team`) outside its `parameters` section. Each distinct URL is one finding.

## Why it matters

The URL points at one environment or site, so the flow reads or writes the wrong data after it is deployed to test or production.

## How to fix

1. Do not use a URL where the platform can use the current environment. In a flow, select **(Current)** as the **Environment** parameter of the Microsoft Dataverse connector's actions that end in "selected environment".
2. Otherwise use an environment variable. Leave its default value empty, because a URL default triggers PO007, and keep no current value in the solution, because a shipped current value triggers PO008. Set the value for each environment when the solution is imported, through a deployment settings file or Pipelines. A required variable that has no value triggers PO002.
3. For relational configuration data, use other tools such as the Configuration migration utility instead of environment variables, as Microsoft's environment variables FAQ advises. Never hard-code the URL.

## Suppress

To accept the finding for now, run `powerops baseline` and use `powerops analyze --baseline powerops-baseline.json`. A baselined finding is matched on solution, rule, component and message.
