# PO022: Power Pages child table permission is not in effect through its parent

Severity: warning

## What it finds

An active child table permission (component type 18 with `parententitypermission` set) in one of two cases:

- It lists a web role that its parent doesn't have. There is one finding per such role. The parent's roles are its own, or, when it has none, its parent's, up the chain; the chain stops at a parent that isn't in the solution or was already visited. A role is named by its web role's name, or by its id when the solution doesn't hold it.
- Its parent is inactive. This is the only finding for that child. When the parent is active but a permission above it is inactive, the child gets no finding, and the parent gets its own.

Each finding is named by the child's name. A child with no roles of its own is quiet, because it takes its parent's. Inactive children don't count.

When the parent isn't found in the solution, or the roles it takes come from a parent further up that isn't, the rule gives no finding. A `parententitypermission` value that is not a GUID string is treated the same way. `analyze` prints one `note:` line on stderr and the exit code doesn't change: `PO022 not checked for table permission '<name>': its parent, or a permission above it, is not found in the solution.` The input it needs is the parent table permission, and the permissions above it, in the same solution.

The rule reads the `powerpagecomponents/` folder of the enhanced data model in a solution, unpacked or in a zip. It does not read the `.powerpages-site/` layout. Learn doesn't document the export layout. The key `parententitypermission` is null in every table permission of the Contoso Real Estate sample, and no export with a child permission was read, so that it holds the parent's id is an assumption from the key's name.

## Why it matters

Learn says a child's roles are inherited from its parent, and that design studio shows an error when a child has a role its parent lacks. It doesn't say how a request treats such a child. It also says that when a parent is deactivated, its children stay active but are not in effect.

## How to fix

Add the missing role to the parent, or remove it from the child; Learn gives both fixes. Activate the parent, or remove the child if it is no longer needed.

Microsoft's own sample sites trip some of the Power Pages rules, so the message says "before Production", not "now".

## Suppress

To accept the finding for now, run `powerops baseline` and use `powerops analyze --baseline powerops-baseline.json`. A baselined finding is matched on solution, rule, component and message.

Two permissions with the same name and parent name (and role, for a role finding) give findings that differ only in their file, so one baseline entry covers both.
