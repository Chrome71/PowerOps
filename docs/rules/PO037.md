# PO037: Flow catches a failure, tells no one and ends as succeeded

Severity: warning

## What it finds

A cloud flow with a failure handler (an action that runs after another on `Failed` or `TimedOut`) where nothing on the failure path tells anyone. The failure path is the handlers and every action that runs after them on `Succeeded`, such as a "finally" step after the catch. The rule fires once per flow, naming the first handler, when all of these hold:

- no action on the failure path, nor any action inside one, is of an outward type: `OpenApiConnection`, `OpenApiConnectionWebhook`, `ApiConnection`, `ApiConnectionWebhook`, `Http`, `HttpWebhook` or `Workflow` (a connector call such as a mail, a web request or a child flow);
- no Terminate action anywhere in the flow has its status set to `Failed` or `Cancelled`;
- no Response action exists anywhere in the flow.

The rule leaves alone a flow with no failure handler, and a flow where a Terminate with a failed or cancelled status or a Response exists, wherever it is. It does not read the handler's content beyond the action types, so a Compose or Set variable on the failure path counts as telling no one.

## Why it matters

Learn says a failure that a later action handles leaves the run succeeded, and a failure that nothing handles makes the run failed. A catch that only sets a variable or composes a value therefore turns a failed run into a succeeded one, and nobody is told.

That statement is on the Logic Apps page for run status. Logic Apps is the engine under cloud flows, and Learn does not state the rule for Power Automate itself, so applying it to cloud flows is an inference. Learn's Power Automate error-handling guidance does describe ending a failure path with a Terminate action set to Failed.

## How to fix

End the failure path with a Terminate action set to Failed, so the run is recorded as failed. Or send the failure to someone: post a message, send a mail, create a task.

If a failure is meant to be ignored, baseline the finding as Suppress says.

## Suppress

To accept the finding for now, run `powerops baseline` and use `powerops analyze --baseline powerops-baseline.json`. A baselined finding is matched on solution, rule, component and message.
