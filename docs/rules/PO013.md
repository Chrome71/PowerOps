# PO013: Root component has no source folder in the YAML layout

Severity: error

## What it finds

In the Dataverse Git integration YAML layout, a root component in `solutions/<name>/rootcomponents.yml` of type table, cloud flow, canvas app or environment variable whose folder is not among the folders that the solution's `solutioncomponents.yml` lists (or the listed folder has no files). The folders are `entities/<schema name>`, `modernflows/<flow id>`, `canvasapps/<schema name>` and `environmentvariabledefinitions/<schema name>`. Microsoft documents the table and canvas app folders; the flow and environment variable folder names, and this list of checked types, come from observed Git integration exports.

The check is folder level: a folder that exists but has incomplete files, for example a canvas app without its app file, is not detected. Other component types are not checked. The rule is quiet for the XML and zip layouts.

Microsoft documents the omission when the component's source files are absent. The case of a folder that exists but that `solutioncomponents.yml` does not list is observed behavior.

## Why it matters

When the folder is packed, the component is left out of the solution while the pack still succeeds with exit code 0 and only a warning. That is why this is an error and not a warning: the pack gives no failure to notice, and the component is missing after import, so a flow, app or table the solution should deliver is not in the target.

## How to fix

Commit the component's folder and list it in `solutioncomponents.yml`, or remove the component from `rootcomponents.yml`. If the folder was never committed, re-export the full solution and take the complete folder from there.
