# PO007: Environment variable default value looks environment-specific

Severity: warning

## What it finds

An environment variable's default value is a URL, a GUID or an email address.

It also reads the default that a cloud flow holds for a variable: the string `defaultValue` of a parameter under `properties.definition.parameters` that is bound to a variable (by `metadata.schemaName`, or by the schema name in brackets at the end of the parameter's name). That finding is left out when the solution has a definition of that variable with the same default, because the definition's own finding already reports it. The finding names the flow and the variable, never the value.

Not read: a default that is not a string (a number, a boolean, an object or an array), and a parameter that is not bound to a variable.

## Why it matters

Default values travel with the solution to every environment, so an environment-specific default silently points other environments at the wrong target.

In the flow case, from observed exports: the value sits in the exported flow file, so it reaches source control and every environment the solution is imported into. Unmodified Microsoft exports hold such defaults too, often the definition's own.

## How to fix

Leave the default empty and set the value per environment at deployment time, or use a default that is valid everywhere.

For a default in a flow, find the parameter bound to the named variable under `properties.definition.parameters` in the file the finding names, and empty its `defaultValue` there (or set a value that is valid everywhere) before packing. It is not verified whether a later save in the designer writes a value back. If it does, accept the finding with `powerops baseline`.
