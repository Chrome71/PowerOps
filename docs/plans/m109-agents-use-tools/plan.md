# M109: Agents use the new tools

## Goal

M98 to M107 gave PowerOps `powerops inventory` (licence drivers and endpoints), the flow rules PO037 to PO042 and the `after` read-back of `deploy apply`, but the skills and specialists an agent follows don't name them, so an agent doesn't run them. The owner also added two things on 2026-11-15: a plan can start from the person's own rough draft, and the licensing reference gives the free Developer Plan what Learn says it covers. This is milestone M109 of the upgrade plan; its section "M109. Agents use the new tools" and its two lines added 2026-11-15 are the authority.

Done when:

1. `skills/powerops-implement/SKILL.md` section 4 step 1 runs `powerops inventory` beside `analyze`, lists its licence drivers and HTTP actions (by flow, action and endpoint kind, never a host) in the pull request, stops under rule 6 of section 3 when a driver's need has no row in the plan's `### Licences` table, and asks nothing when a row covers it. Section 3 rule 7 (the deployment yes) reads each solution's `after` after `deploy apply` and treats exit 1 with "pac reported success, but the target shows" as an import not done.
2. `skills/powerops-plan/references/licensing.md` section 1 says how `inventory` fills the Need rows for an existing solution, driver by driver. Its Developer Plan lines say what Learn says (Data row 3), and no more.
3. `skills/powerops-plan/SKILL.md` section 2 has a step for a draft the person hands over at the start: map it onto the plan's sections, log each choice it settles under `## Log` as the person's answer, quoting the draft, redacted per section 4, and ask only what it leaves open. The round-1 cost tier and the environments question count as asked when the draft settles them.
4. `skills/powerops-review-plan/SKILL.md` item 3: when `Constraints` says Dev is a developer environment, a flow whose expected runs a day, times 30, pass 750 is a Medium finding.
5. `.claude/agents/powerops-automate.md` names `powerops inventory` and PO037 to PO042 in its offline checks. The other names the upgrade plan lists for the specialists are left out because their rules or simulator work aren't on `main` (Data row 6).
6. `docs/PLANNING-SKILLS.md` names `inventory` in the implement row and the draft step in the question rules.
7. Text pins in `tests/PowerOps.Cli.Tests/SkillsCommandTests.cs` hold each of 1 to 4, and the plan skill's word ceiling rises by exactly the words step 3 adds, with the reason in its comment. Plugin copies are regenerated by "Update goldens" and their diff holds only these edits.
8. Behaviour, run once each on the person's subscription, recorded in `decisions.md`:
   - (a) the agent check (upgrade plan section 8 item 2, adapted in Data row 7) passes with the plugin and CLI built at the commit under test;
   - (b) a new smoke scenario `draft` in `tests/smoke/skills-smoke.sh` (a draft naming the cost tier and the route gets no question on either) passes in one local run of that scenario;
   - (c) one headless `powerops-review-plan` run on a scratch plan whose Dev is a developer environment and whose flow runs 40 times a day gives the 750 finding.
9. `docs/ecosystem/changes.md` records the Developer Plan check as a new entry (Data row 5).
10. `dotnet build` (0 warnings), `dotnet test`, `dotnet format --verify-no-changes`, `powerops plan status docs/plans/m109-agents-use-tools` and the leak scan are clean; `tests/eval/`, `tests/golden/`, `skills/powerops-verify`, `skills/powerops-review-security` and their plugin copies are byte-for-byte unchanged.

### Won't build

- A new fixture, rule or command: the agent check uses copies of `tests/fixtures/flow-limits` and `flow-secrets`, so no golden moves.
- Names of rules and simulator work not on `main` (PO043 to PO048, Select and Join): they wait for M101 to M105.
- A change to the `deploy_apply` MCP tool's description (M98's follow-up): skill text covers the agent; the description is a later code change.
- A connector tier list, a Developer Plan row for Copilot Studio or Power Pages (Learn says nothing), and any change to the frozen roles or the eval.
