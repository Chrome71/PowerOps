## Round 0 (the 1.0 fix plan)

### Q2. Does review coverage fail closed on the agent and CI routes?
1. MCP `deploy_apply`, `deploy gate` and the Action require both reports (`verify.md`, `security-solution.md`) ready, current and linked; the person-run CLI warns (recommended by both reviewers)
2. Warnings everywhere (today only `deploy plan` warns)

Answer: 1, "Block agent + CI" (answered by: person, 2026-11-08). M75 builds `--require-reviews` on `deploy apply`, and the three routes always pass it.

## Round 1

Two consequences of the Q2 answer that the fix plan didn't spell out, found while reading the code on 2026-11-09 and asked of the person in one round before the plan was written.

### Q1. The Action would always pass `--require-reviews`, and both example workflows would then always be refused (the promotion example exports the zip in CI, the ephemeral one imports zips no report names). How should the Action handle this?
1. A `require-reviews` input, on by default; a workflow sets `'false'` to import without the check, and the two examples do, with a comment (recommended)
2. Always require, and rework the examples to deploy a zip a role reviewed byte for byte (a larger change, split off)
3. The Action only warns; only MCP `deploy_apply` and `deploy gate` refuse

Answer: 1, "Input, on by default" (answered by: person, 2026-11-09).

### Q2. Until M83, a report records a zip's SHA-256 only when the role ran on that zip; reports for the unpacked folder never do. What does `--require-reviews` accept until then?
1. The zip's hash only, as both reviewers agreed (F-3): for the agent and CI routes the roles run with the managed zip as their solution (file-level parts are then "not verified"), or the person imports with the CLI, which warns (recommended)
2. Also a clean `diff` from an unchanged reviewed folder to the zip (rejected by both reviewers: `diff` doesn't compare roles, tables, columns, forms, views or app role maps)

Answer: 1, "Zip hash only" (answered by: person, 2026-11-09).
