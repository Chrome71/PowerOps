# M51: Read the current Copilot Studio export layout

## Goal

Read the layout that Copilot Studio's new authoring UI exports, so that `powerops diff` reports a changed instruction or a removed tool of such an agent instead of "no changes". This is M51 of the improvement plan written after the live test of 2026-11-04, kept outside the repo because it quotes a private test run. In that test an agent made in the new UI was exported twice, with one sentence added to its instructions, and `diff` said "no changes" (finding F6, claims 48 and 49); so did a copy with its Microsoft Learn MCP tool's folder removed. M50 made the gap visible: today `diff` prints two `note:` lines for these exports, because the reader takes instructions only from a Custom GPT component and tools only from `kind: TaskDialog` data. This agent, on the GitHub Copilot harness, keeps its instructions in `configuration.json` (`agentSettings.instructions.segments[].value`), its tools as `kind: McpTool` components and its Work IQ workloads as six `kind: IQCapability` components.

Done when:

1. `powerops diff` of the scrubbed `v1.zip` and `v2.zip` under `tests/fixtures/agents/new-ui/` prints `changed agent <agent>: instructions changed` with the risk `agent-instructions`, exits `1` and prints no `note:` line, its JSON `notCompared` empty; the same with the arguments swapped.
2. `powerops diff` of `v1.zip` and `v1-no-learn-tool.zip` prints `removed agentTool <the Learn tool>` with the risks `removed-component` and `agent-tool`, exits `1` and prints no `note:` line; swapped, `added agentTool <the Learn tool>` with `agent-tool`.
3. `powerops analyze` of each of the three zips still prints the PO027 to PO031 harness note for the agent (its recognizer is `CLICopilotRecognizer`), and the `analyze-fixtures.*` goldens hold the three zips.
4. `AgentReaderTests` covers `McpTool` data, instructions from segments, missing and malformed segments, a mixed layout (a Custom GPT component beside `configuration.json` instructions, and `TaskDialog` beside `McpTool` tools) and the ambiguity rule; `SolutionDiffTests` covers the new lines and fields.
5. `dotnet build`, `dotnet test` (with `MutationTests`, which now also mutates the three zips), `dotnet format --verify-no-changes`, `powerops plan status .` and the leak scan are clean; the fixture zips' text has no hit for the leak scan's pattern file, no GUID or 32-digit hex id but the two fake ones, no `@`, no `dynamics.com` or `.crm` host, and, unzipped, equals the kept original exports with the scrub map applied; the PR is green on all eight checks.

### Won't build

- A new `diff` component kind or risk label for Work IQ workloads: they are compared inside the `agent` change, so `diff`'s `schemaVersion` stays 2 and a workload change carries no risk label (decisions Q5).
- Reading the connection reference and operation id of a `TaskDialog` tool: the reader keeps what M48 chose; only `McpTool` fills the new fields (decisions Q4).
- Comparing an `McpTool`'s `connectorId`, or any tool's display name and description in `botcomponent.xml`: the connector of the connection reference is compared under `connectionReference`, and a `TaskDialog`'s name and description have not been compared since M49 either; the docs say so (decisions Q12).
- Comparing an agent's authentication mode, recognizer, `agentSettings` keys other than `instructions` (such as the model and web search), `settings`, or components of a type other than 9 and 15 (such as the type-18 feedback setting): not read before M51 either; the docs and the schema say that an empty `notCompared` means the instructions, tools and Work IQ workloads were read, not that the agent is equal (decisions Q12).
- Reading the other tool kinds of the GitHub Copilot harness (`ConnectorTool`, `WorkflowTool`, `ConnectedAgentTool`) and segment kinds other than `StaticSegment`: none was seen in an export; they stay listed as not compared (decisions Q2, Q12).
- Rules that read the new layout: PO027 to PO031 keep reading `TaskDialog` tools and Custom GPT instructions only, as their pages say; the new layout belongs to the GitHub Copilot harness, whose agents they don't read (decisions Q7).
- A new export from Copilot Studio to confirm the layout: optional in the improvement plan and skipped (decisions Q11).
- A `docs/BUILD-PLAN.md` section (decisions Q10).

## Users

- A reviewer who reads a `diff` comment on a pull request for an agent made in the new UI and must see its changed instructions, its added or removed tools and its changed Work IQ workloads.
- A pipeline or agent that reads `diff`'s JSON and needs an empty `notCompared` to mean the agent's instructions, tools and Work IQ workloads were read.

## Assumptions

- Observed in the live test's two exports (2026-11-04, the new authoring UI, recognizer `CLICopilotRecognizer`, template `cliagent-1.0.0`): no type-15 component; `configuration.json` holds `agentSettings.instructions` with `$kind` `Instructions` and one `segments` item of `$kind` `StaticSegment` whose `value` is the instructions text; two type-9 components of `kind: McpTool` with top-level `authMode` (`Invoker`), `connectionReference`, `connectorId` and `operationId`; six of `kind: IQCapability` with `capability` (calendar, files, mail, people, sites, teams) and `access` (`Write`); one type-18 component. The two exports hold the same file paths, so the same schema names, and differ only in the segment's text; the scrub maps each real value to one fake value in all three zips.
- Microsoft Learn, "Export and import agents using solutions" (read 2026-11-04 with the Learn MCP tools): "The agent instructions (main prompt) are included". The file layout is not documented there; it is observed.
- Microsoft Learn, "Work IQ in Copilot Studio (GitHub Copilot)" (read 2026-11-04): Work IQ is added to every new agent on the GitHub Copilot harness, its workloads (SharePoint, OneDrive, Outlook mail, Teams, Calendar, People) are all selected by default and can be cleared, and write operations are on by default. So an `IQCapability` is one selected workload and its `access`; clearing one removes what the agent's Work IQ tool can reach.
- `microsoft/vscode-copilotstudio` (MIT), `src/CopilotStudio.Sync/SYNC-SEMANTICS-CLI.md` at commit `9f6151f`, read 2026-11-04: for CLI agents, the agent metadata `GptComponentMetadata` is "retired for CLI", and `ConnectorTool`, `WorkflowTool` and `McpTool` are CLI-only tool types, beside `ConnectedAgentTool`. So the new layout is the GitHub Copilot harness's, whose agents the agent rules don't read.
- The value of `authMode` of an `McpTool` is compared by `diff` as text; nothing reads its meaning.
