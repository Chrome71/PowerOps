# M117: The sketch judge gives the same verdict twice

## Goal

Fresh judge contexts running `powerops-review-sketch` on the same unchanged sketch gave different gate results and verdicts (M97's three calibration rounds, and the rerun of #166). This milestone closes the gaps the judges named and the ones the runs show, so that each gate's pass or fail follows from a stated, checkable rule: a measurement of `measure.py` where one can be taken, and otherwise a yes/no check with the evidence it names. The owner chose on 2026-11-15 to make this its own milestone before trial 4; it stops before merge for the owner's yes because it touches the calibration evidence.

Done when:

1. Each gap in Data row 2 has its rule where the row says, and nothing else in `SKILL.md`, `baseline.md` or `measure.py` changes meaning.
2. `measure.py` gives the fields of Data row 3; `measure.py --self-test` passes, plants a case for each new field and rule, and still holds every case of #166 (the escape case and the server checks); the sandbox code of #166 (`Page`, `Session`, `CSP`, the Chrome arguments of `run`, the resolver rule and the exits 77) is unchanged.
3. On the five sketches of `tests/sketch-eval/`, `measure.py measure` before and after differs only by Data row 3's changes, every picture of `shoot` is pixel-equal, and the dry run (step 5) states per row and frame what the measured rules give. No rule contradicts the key of row 1 or row 4.
4. Each of the five rows is judged 3 times on the final text (steps 8 and 9), each run in its own fresh context. In every row, all runs give the same verdict and every gate gives the same result; rows 1 and 4 match their key (verdict and keyed gates). The result is reported as "no flip seen in 3 runs" (it is not proof: a gate that flips one run in five agrees in 3 runs about half the time). Any gate or score that still differs is listed in `calibration.md` with its runs; if one still differs after step 9, Done line 4 is not met, and the milestone stops and reports to the owner instead of shipping as done.
5. Where a row's verdict now contradicts `key.md`, the PR does not merge until the owner has answered the key question in chat; a key edit that answer asks for lands in this PR. If the owner keeps the key while a row contradicts it, the PR does not merge (README: every row keeps the verdict its key expects): the milestone stops and reports, and the owner decides in chat what follows. The evidence, each new exemption by name and a recommendation are in Open questions.
6. Plugin copies regenerated by AGENTS.md "Update goldens"; `dotnet build` (0 warnings), `dotnet test`, `dotnet format --verify-no-changes`, `powerops plan status docs/plans/m117-judge-consistency` with no violation, and the leak scan (0 hits, control found) are clean; the PR's CI is all green; the PR is not merged until the owner says yes in chat.
