#### R2. An `.msapp` that is not a zip, or is a valid one over 50 MB, stops every command that loads the solution
- Area: Data rows 3 and 4, `Users`, `Goal` 1 and 5, checklist item 9
- Finding: Rows 3 and 4 refuse (exit 3) an `.msapp` that is not a zip or is over `MaxFileBytes` (50 MB), and `Users` accepts that for every command that loads a solution, including `diff`, `test`, `settings` and `deploy`. For both, the new read changes a working `deploy plan` or `diff` into exit 3.
- Suggested fix: Split the refusals. A file that does not start with `PK` (empty, pointer, placeholder) gives a not-checked note (for example "its .msapp is not a zip and was not read") and no refusal; a `PK` file that fails to open, or any cap hit inside it (entries, entry bytes, depth, anchors, duplicate names), stays a refusal. Read the `.msapp` itself up to `MaxZipBytes` (it is a zip) and keep `MaxFileBytes` for the `Src` entries. Add a test for each, say so in `Users`, and add the LFS sentence to the `analyze` paragraph of `COMMANDS.md` (row 12). If the note texts change, R1's choice decides how many there are.
- Resolution: fixed. A `.msapp` without the zip signature (the test discovery uses for a `*.zip`) is not opened and gives the note; the `.msapp` is read up to `MaxZipBytes`, its `Src` entries up to `MaxFileBytes`; a signed file that fails to open, or any cap inside it, stays a refusal.
