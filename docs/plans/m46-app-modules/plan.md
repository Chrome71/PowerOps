# M46: Model-driven app modules and site maps

## Goal

Read the model-driven app modules and site maps of a solution, unpacked or exported, and report in `analyze` a site map that opens a custom page the solution doesn't carry, and an app over Learn's custom-page limits. This is M46 of Phase 7 ([plan](../phase7-power-platform/plan.md), build-order item 81, release label v0.29.0), with its "Stops if" rule and decision 49 (D10) for inputs an export doesn't hold. F2 has not been read, so the `GenPageId` half of the Error says "not checked" and the reader skips `uxagentprojects/`.

Done when:

- `Solution` has three new fields, `AppModules`, `SiteMaps` and `CanvasApps`, read in an unpacked folder from `AppModules/<name>/AppModule.xml` and `AppModuleSiteMaps/<name>/AppModuleSiteMap.xml` (or their `_managed` files), and in an exported zip from the `AppModule` and `AppModuleSiteMap` elements of `customizations.xml`, the mapping confirmed from a packed copy of `alm-sample` (Assumptions). `CanvasApps` is read from the canvas metadata the parser already loads (a `.meta.xml` in a folder, a `CanvasApp` element of `customizations.xml` in a zip). A folder file whose root element the reader doesn't know, and an app module or site map with no unique name, is an `InvalidDataException` whose message starts with the path. The existing rules give the same findings on every solution as before.
- **PO024, Error:** a site map `Page` target that names a custom page neither in the solution nor in a declared dependency, when the solution holds canvas app metadata. Otherwise, and for every `GenPageId` target, one `note:` line on stderr, with no finding and no exit-code change (D10). `Entity` targets are not checked.
- **PO025, Warning:** an app with more than 25 custom pages, or whose custom pages use more than 10 connectors or more than 20 connection references. A page whose metadata the solution doesn't hold, or can't be read, gives one `note:` line per app.
- Each rule has firing and quiet tests, a page with a dated Learn Sources line and a row in `docs/rules/README.md`. `analyze` has one CLI-level test on a folder and one on a zip of the same solution, built as the packed copy is.
- `alm-sample` reads 1 app module and 1 site map and is quiet on both rules. The goldens change only as the Data section says. `RoleEvalTests` passes with no eval file changed, and `powerops-verify` and `powerops-review-security` keep their blob ids (`69208a2ed044a346bbae9877c8cd74d9e4794df9` and `6a6a6a1fdb71eb16d09cf3ed99406d04a0982a1f`).
- `dotnet build`, `dotnet test`, `dotnet format --verify-no-changes`, `powerops plan status .` and the leak scan are clean, and one `feat:` PR is open.

### Won't build

- Reading `uxagentprojects/`, and an Error for `GenPageId` targets: F2 has not shown that an export carries the folder (the Phase 7 plan's "Stops if").
- Form parsing, role parsing, a no-read-role rule, a dashboard-controls Error, footer controls, a 150-business-rules rule, the form-size and 6-tables-per-generative-page limits as rules, and count reports (the M46 section's "Deliberately doesn't").
- `Entity`, `Url` and `DefaultDashboard` targets, and the `appelements` pages that no site map opens, as Error inputs: the M46 section names only `Page` and `GenPageId` targets.
- App modules in the YAML layout (`solutions/<name>/`): the M46 section names the unpacked folders and the zip.
- The other canvas metadata fields (`CdsDependencies`, `DatabaseReferences` and the rest): M47 reads what it needs. `CanvasAppType` is read, because PO025 must tell a component library from a page (review R1).
- A new fixture: firing cases are hand-built in tests, and two public exports are read for shape and a sanity run only (Assumptions).
- A `--json` or SARIF field for the notes, a `diff` line for app modules, or any schema change.

## Users

- A maker or agent who runs `analyze` on an exported or unpacked solution with a model-driven app, before it goes to Test or Production.
- CI: the Action runs `analyze` with `--fail-on error` by default, so PO024 changes the exit code to 1 where it fires; PO025 changes no exit code unless the job sets `fail-on: warning`. A `note:` line on stderr changes no exit code.
- An agent through the MCP `analyze` tool, which passes stderr `note:` lines on.
- Every command that loads a solution (`analyze`, `baseline`, `diff`, `test`, `settings`, `deploy` and their MCP tools) goes through the same parser, so it now opens the app module and site map files, and a file whose XML is malformed or too deep, whose root element is unknown, or whose app module or site map has no unique name, stops it with exit 3 as any malformed file does today. Before M46 these files were never opened.

## Assumptions

- Learn, checked 2026-11-03. The custom pages overview: "Don't exceed 25 custom pages in a model-driven app"; more increases the wait on the first launch after a publish; each custom page is a separate solution component. The custom page known issues page: across all custom pages, the number of connectors shouldn't exceed 10 and the number of connection references 20, which can increase the wait time; all custom pages share one consent dialog. Add a custom page: a custom page is added to an app's site map in the app designer, and the apps that use a custom page must be republished after the page is published. Dependency tracking for solution components: import fails if the solution doesn't include all required components and the target environment doesn't already have them. The CanvasApp table: `CanvasAppType` 2 is a custom canvas page, 1 an app component library. Design model-driven apps using the classic app designer: each app can have its own site map.
- The packed copy: `pac solution pack --packagetype Unmanaged` (pac 2.14.1, local, no sign-in) of a copy of `alm-sample`, with a placeholder for the plugin DLL the fixture leaves out, gives a zip whose `customizations.xml` holds `<AppModules><AppModule>` and `<AppModuleSiteMaps><AppModuleSiteMap>` with the same children as the unpacked `AppModule.xml` and `AppModuleSiteMap.xml`, and no `AppModules/` or `AppModuleSiteMaps/` entries. The canvas metadata goes the same way: `customizations.xml` holds `<CanvasApps><CanvasApp>` with the `.meta.xml`'s children, and the zip has no `.meta.xml` and no `CanvasApps/src/`, only the `.msapp` and the background image. `--packagetype Managed` gives the same `AppModule` element. Unpacking the unmanaged zip writes `AppModule.xml` and `AppModuleSiteMap.xml`; unpacking the managed one writes only `AppModule_managed.xml` and `AppModuleSiteMap_managed.xml`; the fixture, unpacked as Both, has both files, byte-identical.
- Observed shapes, not documented: microsoft/powercat-creator-kit at `c2d1471211bc64455801e474ec0c71b97e9bc97c` (MIT), `CreatorKitReferencesMDA/SolutionPackage/src`, read for shape: a custom page `SubArea` carries `Page="<canvas app Name>"`; the app module lists its pages as `<appelements><appelement><canvasappid><name>`; it names its site map as `AppModuleComponent type="62"`; the page's metadata has `CanvasAppType` 2. microsoft/gov-apptemplates at `64dabc2652a13a2423ee3fb1d6f4bfe8f33fe1d9` (MIT), `federal/process-and-tasking/src`: custom pages' `ConnectionReferences` is a JSON object keyed by GUID, each entry with a connector `id` such as `/providers/microsoft.powerapps/apis/shared_logicflows`; five of the folder's twelve keys appear in both the Documents page and the Action Assignment page; and the Process and Tasking app lists six `appelement`s, one of them a component library (`CanvasAppType` 1), so it has five custom pages. microsoft/power-platform-skills at `3fb3604b3a7e29e75a5250f1fd574e276b2ba88f` (MIT), `plugins/model-apps/scripts/lib/sitemap-pages.js`, read in source: a generative page `SubArea` carries `GenPageId="<guid>"`, and the SDK it wraps types a `SubArea` as `GenPageId`, then `Entity`, then `Page`, then `DefaultDashboard`, then `Url`.
- PO024 is an Error on the premise that an export whose site map opens a custom page outside the solution declares that page in `MissingDependencies`, as a `Required` node with `schemaName`. Partly observed: the Creator Kit export declares 17 such nodes of type 300 (its pages require a component library outside the solution, with `schemaName` and `solution="Active"`, the environment's unmanaged layer), so canvas apps outside the solution are declared that way. Not observed: an app module or site map that requires a page outside the solution; no public export has one. If the platform doesn't declare it, such an app gets a false Error; the risk is accepted (decisions Q11) and the rule page says so.
- Learn doesn't say how the 10 connectors and 20 connection references are counted from an export. Counting distinct connector ids and distinct `ConnectionReferences` keys is this plan's reading of the observed metadata (decisions Q7), and the rule page says so.
- F2 (an export with a generative page) was not read; it needs the person's yes in a Dev session and is not part of this build.
- Environment facts were not read: this plan changes this repo and targets no environment.
