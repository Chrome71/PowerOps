## Assumptions

- Verified on 2026-11-12 by `powerops-researcher` (Learn only, no tenant call; the Log has each source):
  - Column-level security has separate Read, Read unmasked, Update and Create permissions; a create that sets a secured column without Create fails with `AttributePrivilegeCreateIsMissing`. System administrators are not limited by it.
  - `statecode` and `statuscode` can't be secured, nor lookup, formula and primary name columns.
  - With `EnforceStateTransitions` on, a row can only be changed to an allowed status reason; Learn describes only changes to an existing row, never create, and documents no rule for a non-default status reason at create (the trial is the only evidence that it is accepted).
  - An exception in a synchronous plug-in step cancels and rolls back the operation, on every app; a caller with `prvBypassCustomBusinessLogic` (by default system administrators) can skip custom synchronous logic.
  - The Dataverse trigger of a cloud flow runs asynchronously, outside the transaction, and a flow failure rolls nothing back.
  - A table-scope business rule runs on the server as a synchronous plug-in and can return an error to an API caller, but the same Learn page's FAQ says business rules "aren't executed inside Dataverse", and whether a business rule can use `statuscode` was not checked; so row 6 names a plug-in, not a business rule, for a starting status. Row 6 says "a synchronous plug-in" without a language: whether a low-code plug-in fits is the plan's choice for its product.
  - Power Pages column permissions apply only to the portals Web API, and not on sites with the enhanced authorization model; row 6 doesn't name them.
- `unproven: an agent following the new text starts powerops-prototype in options mode inside the question rounds, asks the pick as a round question within three, and logs the prototype line while the plan is a draft; probed by step 5` (the smoke run, before the closing checks of step 6).
