# Decisions: m20-register

## Round 1

### Q1. How does a plugin start the server, and with which timeout?
1. Both plugins run a bare `powerops` with `["mcp"]` from a `.mcp.json` at the plugin root; the Codex entry adds `tool_timeout_sec: 3600` (recommended)
2. The same, but no timeout in the plugin: the README tells Codex users to raise it in `config.toml`
3. In your own words
Answer: Both plugins run a bare `powerops` with `["mcp"]` from a `.mcp.json` at the plugin root; the Codex entry adds `tool_timeout_sec: 3600`. Claude Code 2.1.303 started the bare command from PATH through a prototype plugin and listed the 12 tools. Codex 0.163.0 parses a plugin's server entries with the same struct as `config.toml`, and a prototype install showed the value it was given (`tool_timeout_sec: 1800.0`). Codex's default is 300 seconds in its code (60 in its docs), and it stops that clock while a form is open; `deploy apply` waits up to 60 minutes for each import, which runs inside the call, so 3600 seconds lets one import finish within the call. 1800, Claude Code's 30-minute idle window, was the first value; it was raised for the import wait. A user's own `[mcp_servers.powerops]` replaces the plugin's entry, so a user can still change it.

## Round 2

### Q4. How does the user say no to the form in Codex, and what shows that it reached the server?
1. Press Esc once in Codex's text form, which sends Cancel because that form has no Decline; choose Decline in Claude Code; the tool's result line ("cancelled" or "declined") is the evidence, and a call with no result is recorded as hanging (recommended)
2. Type a wrong name and submit in Codex, so an Accept reaches the server and is refused for the name
3. In your own words
Answer: Press Esc once in Codex's text form, which sends Cancel because that form has no Decline; choose Decline in Claude Code; the tool's result line ("cancelled" or "declined") is the evidence, and a call with no result is recorded as hanging. Codex's code at `rust-v0.163.0` shows a one-string-field form as a text field with submit and "esc to cancel"; Decline is offered only for a form without properties or one the TUI can't parse. The answer's path back to the server has no key or id mismatch; it is dropped only when Codex has already given up the request (the server cancelled it or the connection closed), and an interrupted turn resolves the form as Cancel. Codex stops the tool timeout while the form is open, so a slow answer doesn't end the call. A wrong name would test the name check, which M19's tests cover, not the user's no that the done-when asks for. Why M19's toy server got no answer stays open (plan, Data).
