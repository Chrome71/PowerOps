#### R1. The `standard` scenario can drop to `quick` after round 1, and then its rows check fails on a correct run
- Area: Data row 18 (the `standard` scenario), Automation, checklist item 9
- Finding: Section 6 of the plan skill says that after each round, "mostly one-word or option-number answers" move `depth` one level down. The simulated user is told "Always pick the option marked (recommended)" and to "reply with only the words you would type back", so it will answer with option numbers, and a `standard` plan can become `quick` after round 1. Under `quick` only data question 1 joins the one round, so data question 2 (rows now and in three years) is never asked, and the scenario's "a question about rows" check fails on a run that followed the skill. The committed script neither pins nor reports the depth of the `standard` plan (the `quick` scenario does check it). The hand run would then "fix" the skill text or the scenario to suit a model that did nothing wrong, and the skill text has no spare words (R2).
- Suggested fix: Say in row 18 how `standard` stays `standard`: for example, the scenario's goal tells the user to answer in a sentence or two of its own words and to ask one question back in round 1, so the engagement rule holds the depth; and the rows check reports the final `depth` and any `depth: standard -> quick` log line in its failure message, so a downshift is read as a downshift. Also give the third-menu pick a condition ("choose D if the menu offers it, else B"), so a menu without D fails as "no sketch option" and not as a mis-sent reply.
- Resolution: fixed (the `standard` goal tells the user to answer in a sentence or two of its own words, so the engagement rule keeps the depth; the third pick is "D if the menu offers it, else B"; the rows check's failure names the plan's depth; row 18 says so)
