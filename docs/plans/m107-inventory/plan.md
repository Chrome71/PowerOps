# M107: `powerops inventory`, what a solution connects to and what makes it premium

## Goal

The practitioner research's most repeated complaint is licensing found out after the build, and it found no tool that reads an export for what makes it premium or lists what it connects to for a data-policy check. This milestone adds one offline, read-only command, `powerops inventory [paths...] [--format text|json|markdown] [--out <file>] [--show-values]`, and its MCP tool `inventory`. Per solution it lists the connectors and who uses them, the custom connectors, the HTTP actions with their endpoint kind, the request triggers, the child flows, the licence drivers from a closed set with a dated Learn source each, and every other connector as "tier not classified". A person can read it and paste it into a pull request: it is redacted by default and never calls a connector standard. M109 later teaches the skills to call it. This is milestone M107 of the upgrade plan drawn from the practitioner research (its section "M107. `powerops inventory`").

### Won't build

- A connector tier list. Every connector that no driver names is listed under `notClassified` with "tier not classified: check the connector's reference page" (the upgrade plan's section 7 default). The Microsoft Dataverse connector used by a flow is such a connector too: only Dataverse as a canvas app's data source is a driver.
- A data-policy (DLP) check, and any sentence about endpoint filtering or environment variables in a policy: Learn and a Microsoft blog disagree there, so the output quotes neither; `httpActions` gives the endpoint kind and, with `--show-values`, the host, for a person to check.
- Licence counts or costs, the tenant's licences (the planning skill reads those), Power Pages capacity, Copilot Studio credits, Power BI, Managed Environments, code apps' own licence terms: no driver. A driver outside Data row 4's closed set needs a new milestone.
- The value or path of a URL, a header, a query, a parameter's value, an id: never printed. `--show-values` adds the host of a literal HTTP endpoint and nothing else.
- Ids of child flows not in the solution, connector ids of a canvas app connection with no id, and the agent behind each solution-level agent connection reference (`AgentConnectionReferences`): the first two print a fixed text, the third shows only under the connector's `references`.
- A new fixture: the made-up cases are built in the tests (Data row 7), so no `analyze` golden changes.
- Skill or specialist text that tells an agent when to run `inventory`: M109.

## Users

- A maker or reviewer who runs `powerops inventory` on an export before a deployment, reads what needs a premium licence and what to check in the data policy, and pastes the Markdown into a pull request or a hand-over.
- An agent that calls the MCP tool `inventory` (M109 adds the skill lines) and quotes its drivers in a plan's `### Licences` table.
- An administrator who checks the connectors and HTTP endpoints against a data policy.

- `custom-connector`, holds: the license-designation page's definition of a premium app, and the Types page (custom connectors included in Premium and Process).
- `dataverse-in-canvas-app`, holds: *Power Apps licensing FAQs* (Learn path `power-platform/admin/powerapps-licensing-faq`, ms.date 2026-10-08) lists Dataverse among the premium features; *Power Platform licensing FAQs* (Learn path `power-platform/admin/powerapps-flow-licensing-faq`, ms.date 2026-10-08).
