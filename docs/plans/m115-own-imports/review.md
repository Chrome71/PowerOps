#### R15. Under zsh's `extendedglob`, `^`, `#` and `~` are glob operators that the tokenizer reads as literal text
- Area: 13 Buildability (an assumption about the shell)
- Finding: The dry-run and strict reads trust a literal word to reach the CLI unchanged. In a folder that holds a file named `--apply` (any segment can make one: `touch -- --apply`), `powerops settings apply /x/s.zip --settings /x/s.json --target "Contoso Test" ^z` and `... --appl#y` both reach the CLI with `--apply`: checked with the fake script under `zsh -f -c 'setopt extendedglob; …'`. Neither word holds `apply`, so both read as dry runs, and the built gate exits 0 on both. Without `extendedglob`, `^z` reaches the CLI unchanged. The hole depends on the person's shell options, which Claude Code's shell snapshot may carry into the Bash tool. The plan doesn't say which shell or options it assumes.
- Suggested fix: In the `powerops` branch, treat a word whose raw text holds `^`, `#` or `~` (any position, beyond the existing leading-`~` and leading-`#` rules) as not literal, for the dry-run test and the strict read.
